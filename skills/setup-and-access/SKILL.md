# Настройка и доступы

Из проверенного корня пакета выполните `python techexpert.py doctor`, затем `init`. Пользователь остаётся в своём ИИ-harness; GUI настраивает источники и не создаёт отдельного агента. После сохранения прочитайте `profile --resolved` с тем же --state-dir и продолжите исходную задачу. Это временное представление настроек адаптеров; исходный профиль с общими ресурсами доступен через `profile`.

Профиль 2 хранит общие узлы, кластеры, экземпляры СУБД и подключения по идентификаторам. В GUI адрес и ссылка на доступ редактируются один раз; имена SQL-баз задаются отдельно. Учитывайте показанный перед сохранением список затронутых баз и источников. После смены подключения прежнее соответствие экземпляра и область прав требуют новой проверки; пользовательские идентификаторы остаются сообщёнными сведениями. Не заменяйте граф плоским представлением из --resolved. Старые профили читаются без перезаписи; `profile-upgrade FILE` преобразует выбранный документ, `profile-impact BEFORE AFTER` показывает конфигурационные зависимости. Эти команды не сохраняют профиль и не подключают источники. Не просите пользователя составлять JSON или вручную описывать всю инфраструктуру.

Импорт стартера читает только выбранный .v8i. Проверка RAS выполняется отдельной кнопкой и читает списки. Адрес SQL из summary не выводится. Для файловой базы SQL/RAS неприменимы; общие ресурсы серверных ИБ связываются с несколькими базами. Данные остаются по разным адресам.

Локальная готовность проверяет поля и связи без обращения к заданным каталогам и executable. Различайте «настроен», «инструмент доступен», «подключение проверено» и «данные нужного периода получены». Для отсутствующих прав подготовьте адресное задание администратору; не включайте WinRM/SSH и не меняйте logcfg из сохранения профиля.

У каждого источника в GUI есть серые пояснения ожидаемого формата и примера, назначение, права и раскрываемая подготовка Windows/Linux. Тот же текст доступен через `source-help tj|jr|source|sql|rac|os`; справка поставляется в пакете и не требует внешнего поиска. Когда ID расследования уже известен, откройте `init --investigation ID`: описание приходит из чата, пользователь уточняет шаблон/время/масштаб и сохраняет профиль для этой ревизии. Не просите заново вводить симптом в GUI.

Команды запускайте из проверенного корня пакета; [общий контракт](../techexpert/references/local-cli.md) задаёт состояние и формат ошибок.

Для журнала на удалённом узле используй [план SFTP и получение выбранных файлов](../techexpert/references/remote-journals.md): транспорт отдельно от формата, сохранение/GET не соединяются, анализ сохранённого capture не переподключается.
