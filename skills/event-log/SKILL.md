# Журнал регистрации

Управляемые операции — jr.import, jr.events и jr.record; точные схемы возвращает `python techexpert.py capabilities ИМЯ`. Агент готовит запрос для operation-run, сохраняет ключ и читает возвращённый artifact_id. Через MCP доступны techexpert_jr_import/events/record, через CodeMode профиль импорта заранее закрепляется в scope.journals. Импорт сохраняет частные байты и хэши; повтор ключа не перечитывает изменившийся оригинал. Чтение событий/записи проверяет сохранённый снимок. Частичный комплект остаётся partial. Прямые команды ниже также доступны.

Прочитайте [карточку ЖР](../../knowledge/methods/jr-readiness.md) и профиль источника. Пользователь предоставляет каталог или согласованный нативный снимок. XML-выгрузка не является пользовательским входом.

Установите ИБ, версию, формат, словарь и части за период, их согласованность и часовой пояс. Отсутствие доступа, отсутствие части и отсутствие событий — разные состояния. Сохраните исходные файлы приватно; не редактируйте действующий ЖР.

Прямой адаптер проверен на реальном ЖР файловой 8.3.27.1989. Запустите `python techexpert.py jr-import "<каталог 1Cv8Log>" --platform-version 8.3.27.1989`; добавьте `--utc-offset=+03:00` только при известном смещении источника. Без смещения нормализованное время остаётся неизвестным. Для заявленного остановленного писателя или предоставленного снимка есть `--consistency stopped_writer|provided_snapshot`; это декларация, не доказательство атомарности. Если комплект меняется при чтении, подготовьте стабильный снимок, не останавливая рабочую систему самостоятельно.

Для самостоятельного снимка SQLite используйте `jr-import FILE.lgd --consistency provided_snapshot`. Выбирайте основной файл из согласованной копии после завершения записи. Адаптер проверяет схему и отказывает при WAL или файле сопровождения. В LGD используется записанное UTC с секундной точностью выборки. `jr-record` возвращает проекцию строки, её номер и хэш исходного снимка. Точная версия записавшей 1С для проверенного образца неизвестна.

Сохраните `artifact_id`. Команда `jr-events ARTIFACT_ID --event '_$Job$_.Start'` выбирает точное имя события; при запуске в PowerShell используйте одинарные кавычки для символов `$`. Пагинация: `--offset 0 --limit 20`. `jr-record ARTIFACT_ID s2:r1` проверяет целостность и показывает исходную логическую запись, диапазон байтов и хэш. Подставляйте возвращённый идентификатор, а не предполагаемый номер строки.

После сообщения о повторении возьмите `occurrence_window` из `investigation-progress` и передайте его как `window` в `jr.events`. В `jr-events` и `context-read jr-events` используйте `--start` и `--end`. Начало включается, конец исключается. Сравните `coverage.records_in_window`, диапазон и `parse_status` с запросом. При неизвестном смещении `records_in_window` остаётся неизвестным. Часы и принадлежность запуска проверяйте по отдельным свидетельствам.

Проверяйте `issues`, неизвестные ссылки словаря и `complete_incident_coverage`. Для связи с запуском ищите независимое подтверждение принадлежности и времени жизни сеанса.

Команды запускайте из проверенного корня пакета; [общий контракт](../techexpert/references/local-cli.md) задаёт состояние и формат ошибок.

Для каталога или ZIP сначала выполните `input.inspect`. В `jr.import` передайте `input_plan`, выбранные `members` и исходный `path`. Выберите словарь и части одной группы либо один файл LGD. В CodeMode разрешение `scope.journals` задаёт исходный корень и параметры импорта. Для защищённой выдачи используйте `context-read` с политикой расследования.

Для LGD по SFTP выбирайте каталог согласованного снимка. `remote.parse` проверяет полный сохранённый каталог и выбранные байты.
