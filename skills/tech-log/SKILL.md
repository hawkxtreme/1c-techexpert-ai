# Технологический журнал

Используйте [контракт CLI](../techexpert/references/local-cli.md): source-check, analyze, coverage, show, events и evidence. [Проверка покрытия](../techexpert/references/source-coverage.md) отделяет доступ/разбор от периода и пригодности для вопроса. Перед разбором задайте подтверждённые версию, кодировку, размещение и формат времени; plain/folders сами не определяют вид timestamp.

Для обычного ТЖ подготовь общий манифест schema2 по известным данным источников. Не требуй scenario=SC-01, UUID задания или выдуманных database/node/process/epoch/run. Схема1 и контролируемые маркеры остаются отдельными профилями. Найди кандидатов по известному периоду через events --start/--end либо case.events.window: выбирается записанное время в [start,end), не предполагаемый интервал CALL. Связь кандидата с действием и согласованность часов проверяются отдельно. При приблизительном времени расширяй поиск в разрешённой области, сохраняя неопределённость.

До причинной интерпретации прочитайте source_coverage нового случая либо выполните coverage для сохранённого. Source-check нужен, если до импорта требуется оценить объявления/доступы; он не сохраняет снимки. Не повторяйте его вместе с analyze без необходимости. Диапазон первой/последней записи и пересечение диапазонов не доказывают полноты; числовое сопоставление времени не подтверждает синхронизацию часов. Для редкого инцидента используйте сохранённый план и данные после сообщения о повторении в том же чате.

Для большого стабильного локального ТЖ выбери `external_window` в источнике schema2. Укажи `start` и `end` с часовыми поясами и `max_retained_bytes`. Покажи размер, место и предел из `tj-reference-plan MANIFEST` или `source.check` с `reference_preview: true`. С утверждённым `plan_sha256` вызови `case.analyze` с `reference_sha256`. Программа дополнительно закрепляет пару `manifest` и `sha256` в `scope.reference_reviews`. После ротации используй сохранённые диапазоны, `reference_window` и `original_location`. Таймстамп записи и границы файла оставляют покрытие сбора и привязку к заданию непроверенными.

Для файлов, каталогов и ZIP используйте `input.inspect` через MCP либо запрос `operation-run`; покажите пользователю состав и размеры. После выбора агент готовит манифест с ID членов каталога и вызывает `case.analyze` с `input_plan`. Формат и временной профиль задаются для каждого выбранного файла; имя файла не даёт часового пояса. Повтор прежнего ключа читает сохранённый план, а не обновляет исходники. Новый состав требует отдельного просмотра. Для манифеста с ID членов каталога source.check без input_plan не применим: читай покрытие из case.analyze и сохранённого coverage. Для ЖР и JSON метрик ОС/APDEX используй отдельные адаптеры с тем же планом просмотра и выбранными members. Исходники подключаются каталогом/Git без архивов.

Если исходный локальный ТЖ дописывается, агент может явно задать read_mode="tj-prefix-v1" в источнике существующего native-профиля. case.analyze/analyze сохраняет ровно начальную часть[0,N), проверенную двумя чтениями одного файла; source.check/source-check лишь проверяет её без сохранения сырых байтов. Не включай режим для других форматов, членов input_plan или несогласованного ЖР. Читай acquisition: границы, время, file_identity, snapshot_id, наблюдённый рост, framing и ограничения. Незавершённый хвост сохранён как байты, но не является принятым событием; frame boundary не доказывает корректность записи. Размеры и число попыток ограничены. При prefix_changed/source_truncated/source_replaced не запускай новый ключ автоматически: пригодные другие источники остаются доступны, следующий снимок — отдельный явный шаг. Не обещай атомарность, отсутствие недетектируемой перезаписи/ABA, непрерывность, поддержку живого писателя платформы или согласованность файлов. Один snapshot_id не задаёт причину или ИБ; не объединяй события разных реальных файлов по равенству текста.

Просматривайте записи страницами и по свойствам. Нужен исходный event и точное свидетельство source:line, не только агрегат. Многострочные значения, дубли свойств и ошибки разбора сохраняют ограничения. Unknown не заменяется нулём.

Сохранённый ТЖ читается блоками; events/evidence проверяют SHA-256 всего снимка, включая непросмотренную часть. Ошибка целостности останавливает выдачу страницы. Ограничения импорта остаются прежними: 16 МиБ на файл, 64 МиБ на комплект, 100 000 попыток разбора и 256 КиБ на запись. Потоковый запрос не доказывает полноту большого журнала и не подтверждает активно меняющийся оригинал. ZIP подключается отдельным явным планом приёма.

CALL/SCALL описывает вызов, не целое фоновое задание. UUID, процесс, сеанс, эпоха жизни, ИБ и узел сопоставляются независимо. Только проверенный профиль маркеров даёт ограниченную привязку к запуску SC-01. Для изменения сбора перейдите к [logcfg](../logcfg/SKILL.md); успешный разбор не подтверждает полноту окна.

Команды запускайте из проверенного корня пакета; [общий контракт](../techexpert/references/local-cli.md) задаёт состояние и формат ошибок.

После получения новой части используй source.compare через operation-run/MCP/CodeMode: before/after — выбранные сохранённые {kind:case|artifact,id,source_id}. Агент берёт ID из расследования, пользователь не заполняет техническую форму. В CodeMode нужны оба целевых case/artifact в scope. Сравнение читает сохранённые байты и связанные каталоги, не обращается к оригиналам и не снимает новый журнал. Разделяй byte_relation, observation и input_duplicate. Равенство текста/хэша без происхождения не доказывает один реальный эпизод. Прежние захваты без reader_scope остаются unknown; метки пользователя не заменяют наблюдённый namespace. При prefix_extended suggested_after_range включает старый незавершённый хвост; это подсказка чтения, без объединения событий и гарантии непрерывности. frame_completed означает завершение фрейма, не проверку валидного события. При изменении profile/context/collection повторно интерпретируй текущий источник целиком. Сохраняй новую ревизию расследования, прежнюю оценку не переписывай.
