# Проверка первого запуска

Пользователь уже находится в своём ИИ-harness. Не настраивай новую модель/API-ключ. Прочитай `AGENTS.md` и точку входа `skills/techexpert/SKILL.md` именно этого пакета. Если Python отсутствует, сообщи единственное необходимое действие — установить поддерживаемый Python3.11+ штатным способом для своей ОС; автоматическую установку этот комплект не выполняет. Не требуй прав администратора, 1С, SQL/RAC или серверной лицензии для анализа готовых файлов.

Из проверенного корня пакета получи SHA-256 прочитанной точки входа, нормализуя только CRLF→LF:

```powershell
python -c "import hashlib,pathlib; print(hashlib.sha256(pathlib.Path('skills/techexpert/SKILL.md').read_bytes().decode('utf-8').replace(chr(13)+chr(10),chr(10)).encode('utf-8')).hexdigest())"
python techexpert.py readiness --entrypoint-sha256 HASH
```

Агент передаёт фактический хэш. Для выбранного расследования добавь `--investigation ID` и при необходимости `--state-dir КАТАЛОГ` перед командой. Это свидетельство агента о прочитанном файле. Получай хэш из прочитанной точки входа текущего пакета.

`ready_for_supplied_files` означает, что комплект проверен, текущий агент подтвердил вход и измеренное свободное место соответствует порогу ядра. Источники проверяются отдельно. `needs_harness_confirmation` требует подтвердить вход. При `blocked` команда возвращает код 2 и указывает повреждённые компоненты. Восстанови совместимый комплект с сохранением частных данных.

При `state_storage_blocked` (`readiness` возвращает код 2) или `state_space_insufficient` используй `state_storage` и действие `check_state_storage`. Назови измеренный объём и порог, если причина в месте. Сохранённое расследование продолжай с его прежней папкой через `--state-dir`. Если пользователь указал локальную папку для новых расследований, выполни `state-location`, затем `state-location --select КАТАЛОГ --expected-revision N` с полученной ревизией. Повтори `readiness` и вызови `init` с сохранённым выбором.

CLI читает выбор при запуске. MCP читает его при первом вызове, который проходит проверку хранилища. Уже привязанный процесс MCP продолжает читать свою папку. Для нового выбора используй новый сеанс MCP. Временный `--state-dir` действует на конкретный запуск. Выбор папки записывает только настройку, а сохранённые расследования остаются по своим адресам.

Проверка использует только каталог установленного пакета и локальное состояние; сохранённые адреса источников не открываются. `profile.not_configured` отделён от `profile.invalid`. При invalid не сохраняй пустой профиль поверх старого: сохрани данные и разбери отказ с агентом. Закреплённый профиль расследования читается вместо чужого текущего. SQL/RAC для файловой ИБ имеют `not_applicable`, для неизвестного/серверного режима — `not_checked`. Не путай неприменимость с отсутствием данных или несовместимостью инструмента. Подключения проверяются отдельными адаптерами по разрешённому плану.

Если для следующего шага нужны настройки:

```powershell
python techexpert.py init --entrypoint-sha256 HASH --investigation ID
```

Без выбранного расследования опусти `--investigation`. Init возвращает тот же readiness и URL временной защищённой loopback-сессии. При недоступном хранилище URL пустой. Используй действие из readiness. Проверь реальную доступность страницы. Сохранённый профиль подхватывается повторно. Если инструменты и настройки уже готовы, продолжи в чате.

Отдельная кнопка «Проверить на примере» или команда `demo` выполняет только комплектный синтетический SC-01, сохраняет `case_id` и квитанцию без изменения рабочего профиля/расследования и без запуска платформы/сборщика. Перед запуском проверяются комплект и точный безопасный вход. Повторный POST в GUI читает проверенный сохранённый результат; повреждение не вызывает автоматический повтор. Явный CLI `demo` создаёт новый пример.

После возврата из GUI агент вызывает `readiness` и читает `demonstration`: `not_run`, `completed` либо `damaged`; completed содержит ID, версию, интервалы и проверенную целостность отчёта и входа. Для деталей используй `show CASE_ID`/`evidence CASE_ID s1:1` в том же состоянии. Объясни: очередь240с, выполнение2460с, всего2700с; заявленные обычные300с не измерены. Причина из трёх отметок неизвестна, native-совместимость этим примером не проверяется. Затем продолжи исходную задачу в том же чате; демонстрация не является пользовательским инцидентом.
