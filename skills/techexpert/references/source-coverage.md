# Покрытие ТЖ для SC-01

Эта проверка отвечает, какие наблюдения пригодны для следующего вопроса. Она не устанавливает причину, полноту сбора, синхронизацию часов, тождество ИБ или принадлежность записи конкретному запуску. Автоматически оценивается только нативный текстовый ТЖ поддержанного профиля8.3.27.1989; нормализованные события, runtime/HTTP/CSV/исходники и отдельный ЖР остаются вне этой проверки.

Используйте общий `--state-dir` перед командой. Агент готовит манифест из разговора; пользователь не пишет JSON. Для нового случая обычно достаточно analyze: в ответе уже есть source_coverage и source_acquisition. До причинной интерпретации прочитайте их. Если ещё до импорта надо выяснить доступность/профили, отдельно выполните:

```powershell
python techexpert.py source-check MANIFEST --start 2026-11-16T10:00:00+03:00 --end 2026-11-16T10:05:00+03:00 --require-event SDBL --require-field Sdbl
```

Это read-only просмотр явно выбранных файлов: снимки временно находятся в памяти, состояние не создаётся. Изменение файла между просмотром и импортом даёт другой снимок/хэш; прежний preflight не подтверждает новый вход. Проверяйте итоговую source_coverage сохранённого случая, не подставляя старую проверку вслепую. Не выполняйте source-check и analyze подряд без необходимости повторного чтения.

Для продолжения, в том числе старого случая:

```powershell
python techexpert.py coverage CASE_ID --start 2026-11-16T10:00:00+03:00 --end 2026-11-16T10:05:00+03:00 --require-event SDBL --require-field Sdbl
```

Coverage проверяет receipt отчёта/манифеста и SHA/размер сохранённых ТЖ, повторно разбирает только частные снимки с исходным профилем и бюджетом записей. Исходные пути не разрешаются и не читаются. Старый отчёт, Investigation и его assessment не изменяются. Ответ содержит исходный case_report_sha256, текущую версию расчёта и параметры; это производный read-only результат. При повреждении снимка — ошибка целостности, без повторного импорта из оригинала. У старых случаев без сведений о неудачном чтении причина недоступности остаётся неизвестной; без исходного бюджета нельзя выдать полный повторный разбор.

Оба параметра времени передаются вместе. Сравнение использует полуоткрытое окно `[start,end)` по записанному времени; UTC-offset обязателен, `-00:00` не принимается. До16 различных имён событий и16 полей, точный регистр. Поля проверяются внутри окна среди запрошенных типов событий, либо среди всех наблюдаемых событий, если типы не заданы. `usable_records` требует непустого однозначного значения. Пустые и повторные неоднозначные значения отделены. Первые несколько свидетельств содержат source:line, SHA и позиции; читайте их через evidence.

При необходимости агент добавляет в манифест `incident_window: {start,end}`. Необязательный `collection` источника принимает только `events` (до64 имён), `filters` (до2048 символов) и `window: {start,end}`. Это заявление пользователя с `user_declared_not_verified`, не прочитанный logcfg. Контекст node/process/epoch также остаётся заявленным. Общий путь, имя DataBase/process или близкое время не подтверждают тождество. Для конкретного задания используйте независимую job_correlation и events --linked-run; coverage не подменяет этот фильтр и не суммирует длительности CALL/SCALL.

Доступность различает captured, not_found, access_denied, read_error, byte_limit, changed_during_read, unsupported_format/profile, invalid_source, duplicate_source и conflicting_profile. В инспекции неподдержанные объявления не открываются, пригодные части показываются отдельно. Строгий analyze по-прежнему требует поддержанных непротиворечивых объявлений; исправьте их с агентом перед импортом. Пустой файл, неверные записи, отсутствие записанных времён внутри окна и недостаточность полей — разные состояния.

Observed first/last — минимум/максимум принятых записанных времён. Даже если диапазон охватывает инцидент, внутри него может не быть ни одной записи. Это не проверка потерь/ротации, не доказательство работы сборщика и не подтверждение часов. Неприсутствующий тип событий мог не собираться или отфильтровываться. Исключение из заявленного списка отмечается как not_collected_declared; противоречащие ему фактические записи остаются видимыми. `can_establish_absence` всегда false. Не объявляйте отсутствие блокировок/HTTP/SQL-проблем по отсутствию событий.

Если у collection задано окно, исключение события применяется только к запросу внутри этого окна; при выходе за него неизвестность сохраняется. Запись за пределами периода настройки не считается противоречием настройке этого периода. Сопоставление этих периодов по-прежнему числовое, с непроверенными часами.

Сохраняются исходные пределы:32 файла,16МиБ на обычный файл,64МиБ суммарно,100000 попыток записей. В одном источнике выводятся до100 названий событий/полей и20 ошибок, остальное отмечается усечением; запрос конкретного имени считается по принятым записям независимо от краткой сводки. Read-only проверка не обходит лимиты, не подключает СУБД, не запускает платформу/сборщик и не меняет logcfg или рабочие базы.
