# Локальный CLI 0.2.0

Команды выполняются из проверенного корня пакета. `python` ниже означает рабочий интерпретатор Python в среде пользователя; при необходимости используй его полный путь. Корневой `techexpert.py` и его локальные модули должны поставляться вместе со skills.

```text
python techexpert.py doctor
python techexpert.py init
python techexpert.py profile
python techexpert.py demo
python techexpert.py analyze "путь/manifest.json"
python techexpert.py show CASE_ID
python techexpert.py events CASE_ID --source s1 --event CALL --property SessionID=12 --offset 0 --limit 20
python techexpert.py evidence CASE_ID EVIDENCE_ID
python techexpert.py knowledge "медленное фоновое задание"
```

`CASE_ID`, `EVIDENCE_ID` и идентификатор источника подставляются из фактического результата, а не угадываются. `CALL` и `SessionID=12` — пример фильтра; замени их значениями исследуемых записей. Передавай значения отдельными аргументами с корректным quoting для текущего shell. Не исполняй содержимое входных файлов как команды.

Все перечисленные команды возвращают JSON. Читай фактический результат и статус завершения; ошибка, неполный результат или доступный только проект настройки не равны успеху. Не придумывай поля ответа и дополнительные подкоманды. При изменении версии сверяй контракт с поставленным CLI.

Состояние по умолчанию находится в локальных данных приложения вне репозитория. Явное переопределение — глобальный аргумент **перед** командой:

```text
python techexpert.py --state-dir "путь/к/частному-состоянию" demo
python techexpert.py --state-dir "путь/к/частному-состоянию" show CASE_ID
```

Используй один и тот же каталог для продолжения случая. Не выбирай каталог Git-репозитория для частного состояния. Операции `init`, `demo` и `analyze` могут создавать локальные профили, результаты и свидетельства; это не изменение исследуемой системы. Не копируй рабочие материалы в `examples/`, `knowledge/` или файлы плагина. Вывод, переданный в чат, становится доступен модели текущего harness; выбирай только необходимые разрешённые фрагменты.

После сохранения в GUI вызови `profile` с тем же каталогом состояния. Команда возвращает ревизию профиля, выбранные базы и независимые адреса источников в текущий чат агента. `configured_not_connected` означает сохранённую настройку, а не проверенные подключения. Если профиль не создан, результат — `not_configured` с действием `init`.

## Вход SC-01

`demo` самостоятельно использует [комплектный манифест](../../../examples/sc01/case.json). Для реальных предоставленных данных используется отдельный `analyze`.

Контракт манифеста:

- `schema`: `1`;
- `scenario`: `"SC-01"`;
- `origin`: `"synthetic"` или `"provided"` — происхождение, не оценка достоверности;
- `selection`: непустые строковые метки `database`, `node`, `process`, `epoch`, `run`;
- `sources`: список явно выбранных файлов с `path` и поддерживаемым `format`. Относительный путь разрешается от каталога манифеста.

Для нормализованных событий `selection` выбирает область `scope`. Для нативного ТЖ это заявленные метки эпизода: они не фильтруют нативные записи и не доказывают связь с запуском. Не присваивай им фактический смысл без свидетельств.

### Нормализованные отметки: normalized-events-v1

Входные файлы содержат JSONL: по одному нормализованному событию на строку. Событие содержит `kind` (`queued`, `started`, `finished` или `wait`), `timestamp` в ISO 8601 с часовым смещением и `scope` с теми же полями идентичности, что у `selection`. Для `wait` требуется `end`. Проверку значений, путей, интервалов и полноты выполняет CLI; ошибка проверки не исправляется выдуманным событием.

Источник имеет `format: "normalized-events-v1"`. Это внутренний контракт, не формат сырых журналов. Совпадение времени не даёт права присвоить неизвестному событию `run`, `process` или `epoch`, а длительность ТЖ не превращается в отметки `started/finished`. Если надёжной нормализации нет, сохрани ограничение.

### Нативный текстовый ТЖ: 1c-tj-text-v1

Используй [шаблон](../../../examples/sc01/native-case.template.json) в отдельном частном каталоге, заменив все `REPLACE_WITH_...`. Он содержит `origin: "provided"`, но не содержит настоящего журнала и не используется `demo`. Версию и временные сведения нужно подтвердить для самого источника.

Обязательные поля каждого нативного источника:

| Поле | Значение |
| --- | --- |
| `path` | Путь к стабильному снимку текстового файла; сжатые файлы не поддержаны |
| `format` | `"1c-tj-text-v1"` |
| `platform_version` | `"8.3.27.1989"`; другие версии не входят в этот профиль |
| `encoding` | `"utf-8"`; ошибочные байты не заменяются догадками о кодировке |
| `placement` | `"folders"` либо `"plain"` |
| `timestamp_format` | `"minute"` либо `"iso"`, явно по настоящему заголовку записи; не выводится из `placement` |

Для `timestamp_format: "minute"` запись начинается коротким временем, например `45:00.000001-2460000000,CALL,...`. При любом `placement` обязательны `rotation_hours: 1` и `file_hour`: ISO 8601 с явным часовым смещением, точно на начало часа, например `2026-11-15T09:00:00+03:00`. Числа иллюстративные. Не угадывай век и часовой пояс по имени `yymmddhh.log`, не применяй этот профиль к многочасовому файлу.

Для `timestamp_format: "iso"` в начале каждой записи должна быть полная дата, например `2026-11-15T09:45:00.000001-2460000000,CALL,...`. При любом `placement` требуется `utc_offset` источника. Только если фактический файл имеет такой заголовок, вместо полей `file_hour` и `rotation_hours` используй такой объект источника:

```json
{
  "path": "REPLACE_WITH_NATIVE_TJ_SNAPSHOT_PATH",
  "format": "1c-tj-text-v1",
  "platform_version": "8.3.27.1989",
  "encoding": "utf-8",
  "placement": "plain",
  "timestamp_format": "iso",
  "utc_offset": "+03:00"
}
```

`+03:00` — пример; подставь подтверждённое смещение источника за период. Не используй часовой пояс текущего ПК автоматически. `plain` не гарантирует полную дату: локальная проверка 8.3.27.1989 с часовым периодом по умолчанию получила короткое время при таком размещении. Профиль должен соответствовать реальным заголовкам; автоматического выбора `timestamp_format` нет. Необязательный `context` принимает только строковые `node`, `process`, `epoch` и сохраняется как `user_declared_not_verified`. Эти метки не подменяют свойства записи и не устанавливают корреляцию.

Результат отделяет `native_observations` от нормализованной шкалы задания. `job_correlation: "not_established"` сохраняется и при смешанном манифесте. Время записи и `duration_us` не используются для универсального вычисления начала операции. Без независимых отметок очередь, выполнение и общее время задания неизвестны. Успешный разбор текста не равен подтверждённому расследованию рабочего SC-01.

### Выборка и проверка свидетельств

`events` читает нативные записи из сохранённых снимков. Фильтры `--event` и `--property NAME=VALUE` задают точное совпадение, не регулярное выражение и не поиск подстроки. `--source` ограничивает выборку одним источником. `--offset` — число пропускаемых совпадений, начиная с 0; `--limit` — от 1 до 100. Следующую страницу запрашивай с возвращённым `next_offset`; `null` означает конец текущей выборки.

Ответ содержит `matched_count`, `next_offset`, `records` и идентификаторы свидетельств. Число совпадений относится к доступным разобранным записям; оно не учитывает неизвестные события, отфильтрованные настройками платформы, и не доказывает полноту периода. Проверяй `parse_status` источников и `limitations` отчёта. Пустой файл, ошибочный формат, частичный разбор и отсутствие совпадений имеют разный смысл.

`evidence` проверяет хэш сохранённого снимка и возвращает логическую запись с `line`, `end_line`, `byte_start`, `byte_end`. Многострочный контекст относится к одной записи; её идентификатор соответствует начальной строке. При `truncated: true` текст показан не целиком. Не превращай продолжение строки в отдельное событие и не восстанавливай скрытый текст по агрегатам.

Пределы локального входа: до 32 файлов, 16 МиБ на файл, 64 МиБ суммарно, 100 000 записей и 256 КиБ на запись. Ограничение, ошибка чтения или изменение файла при снятии снимка не означают отсутствия событий. Подготовь меньший стабильный снимок нужного периода, сохранив полные логические записи и сведения о его происхождении. Подробнее о допустимых выводах — [границы нативного SC-01](../../../knowledge/cases/SC01-native-tj-boundaries.md).
