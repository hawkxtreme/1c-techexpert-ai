# Клиентская диагностика

Начните с `python techexpert.py knowledge "динамический список"` и карточки [клиентского обновления](../../knowledge/methods/client-refresh.md). Измерьте отдельно серверную операцию и время до возвращения управления пользователю. Зафиксируйте открытые формы, отборы, права и клиент.

Testpilot — возможный канал управляемого TestClient; проверяйте фактически установленный пакет и его API по [репозиторию разработчика](https://github.com/ROCTUP/1c-testpilot). Полный профиль SC-05 в текущем комплекте ещё не подтверждён; не придумывайте команду techexpert testpilot.

Сравните одинаковое действие с исходным набором окон и после адресного закрытия одного кандидата. Отсутствие EXCP не доказывает отсутствие клиентской задержки. Сопоставьте обновления списков с исходниками и ТЖ, затем отдельно проверьте правильность записи и пользовательскую длительность. Управление рабочим клиентом должно входить в разрешённый план.

Команды запускайте из проверенного корня пакета; [общий контракт](../techexpert/references/local-cli.md) задаёт состояние и формат ошибок.
