# Клиентская диагностика

Уточни в чате действие, признак готовности интерфейса, исходные открытые окна, отборы, клиента и права. При задержке после записи проверь, какие открытые формы и динамические списки обновляются. Для гипотезы и проверки используй [карточку клиентского обновления](../../knowledge/methods/client-refresh.md).

## Подготовленный TestClient

1. Для запуска нужен отдельный тестовый тонкий клиент Windows 8.3.27.1989 в режиме TestClient с известным локальным портом и доверенное Python-окружение с Testpilot 1.9.2. Подготовка и запуск клиента описаны в [руководстве Testpilot](https://github.com/ROCTUP/1c-testpilot/blob/46eaa7454292e3e8a8159f631190221b5ffdce72/docs/PYTHON_TESTING.md).
2. Выполни `python techexpert.py client-endpoint PORT`. Команда читает локальную таблицу портов и возвращает `endpoint` с `port`, `pid` и `lifetime`. Сверь процесс с выбранным клиентом. Подставь этот объект и абсолютный путь к Python окружения в `client.observe`. Сообщённый вид базы передай как `database_mode`.
3. Без `navigation` операция читает активное окно и накопительные клиентские счётчики. Для проверочного открытия списка отдельно согласуй `navigation.link` вида `e1cib/list/Документ.Имя` и `navigation.ready_form` вида `Документ.Имя.ФормаСписка`. Открытие может запустить прикладные обработчики. Проведение, запись и клики выполняются оператором в согласованном тесте.
4. Используй управляемый `operation-run REQUEST.json` либо `techexpert_client_observe` через MCP. `capabilities client.observe` возвращает схему. Для программного вызова закрепи точные параметры в `scope.testpilot[].settings`. Повтор ключа открывает проверенный снимок. После обрыва уточни фактическое состояние клиента по сохранённым данным и у оператора.

## Эпизод из файла

`client.import` или `python techexpert.py client-import PATH` принимает частный UTF-8 JSON `client-episode-v1` до 512 КиБ. Для CodeMode разреши точный путь в `scope.client_episodes`. Возьми сохранённый `client-episode.json` либо собери запись по отметкам оператора.

```json
{
  "schema_version": 1, "origin": "manual", "driver_version": null,
  "started_at": "2026-01-15T10:00:00+03:00", "finished_at": "2026-01-15T10:00:20+03:00",
  "session": null, "before": null, "after": null,
  "action": {
    "label": "Открытие отчёта", "started_at": "2026-01-15T10:00:05+03:00",
    "status": "reported", "returned_ns": null, "ready_criterion": "Появилась таблица отчёта",
    "ready": {"at": "2026-01-15T10:00:15+03:00", "elapsed_ns": null, "form_name": null}
  },
  "issues": []
}
```

Замени отметки фактическими со смещением часового пояса. При неизвестном результате оставь `ready` пустым (`null`). Ручной промежуток остаётся сообщённым оператором.

## Интерпретация

Сохрани `artifact_id` в расследовании. Используй ответ инструмента, момент наблюдения нужной формы и изменение счётчиков как разные свидетельства. Единицы счётчиков и принадлежность записи конкретному запросу, ИБ или фоновому заданию требуют проверки. Длительности записи и обновления форм остаются неизвестными до отдельных измерений. Для проверки исправления сравни то же действие при сопоставимых условиях и отдельно проверь правильность результата. В общий черновик переноси только просмотренное обезличенное описание наблюдений.

Запускай команды из проверенного корня пакета. [Общий контракт CLI](../techexpert/references/local-cli.md)
