# Первый прогон на Windows Dev

Эта инструкция относится к Git-ревизии, которую вы перенесли на Dev. Снимок согласованных требований находится в [ТЗ](requirements.md). Первый прогон проверяет настройку и расследование на том же классе задачи, что и файловый SC-01. На Dev источники включают серверную ИБ, кластер 1С, SQL Server и выбранные журналы.

## Перенести комплект

Откройте PowerShell на Dev в каталоге, где нужен checkout, и клонируйте рабочую ветку из GitHub.

```powershell
git clone --branch feature/sc01-local-pilot https://github.com/hawkxtreme/1c-techexpert-ai.git
Set-Location .\1c-techexpert-ai
git rev-parse HEAD
python --version
```

Сверьте `HEAD` с нужным коммитом в рабочей ветке. В репозитории есть код, навыки, знания и безопасные примеры. Лицензия, доступы и базы берутся из действующего Dev-контура. Сохранённое расследование можно перенести частным экспортом. [Рабочая ветка](https://github.com/hawkxtreme/1c-techexpert-ai/tree/feature/sc01-local-pilot) · [Частный экспорт](../skills/report-and-evidence/SKILL.md)

## Перед запуском

Запускайте агентный клиент и команды под Windows-учётной записью, которая будет читать источники. Если агент выполняет команды на Dev, откройте локальную ссылку мастера с рабочего стола Dev. Из корня checkout доступен проектный навык `$techexpert`.

Проверьте комплект в отдельной локальной папке. Демо запишет туда синтетический пример.

```powershell
$TechExpertPreflight = Join-Path $env:LOCALAPPDATA ('techexpert-dev-preflight-' + [guid]::NewGuid().ToString('N'))
python techexpert.py --state-dir $TechExpertPreflight doctor
python techexpert.py --state-dir $TechExpertPreflight readiness
python techexpert.py --state-dir $TechExpertPreflight demo
```

Подготовьте название и версию Dev-ИБ, адрес существующего RAS и путь к установленному RAC. Для SQL Server понадобятся экземпляр, порт, имя БД и разрешённая учётная запись. Адаптер проверен на SQL Server 2022. [RAC](../skills/rac/SKILL.md) · [SQL Server](../skills/sql-server/SKILL.md)

Запишите доступные исполнителю пути к ТЖ, ЖР и исходникам по отдельности. Для произошедшего эпизода укажите начало, конец и часовой пояс. Для будущего эпизода согласуйте окно наблюдения и вернитесь в тот же чат после сообщения о событии. Для метрик определите узлы 1С, SQL и хранения, которые входят в проверку. [ТЖ](../skills/tech-log/SKILL.md) · [Метрики узлов](../skills/os-metrics/SKILL.md)

## Промпт для первого теста

Скопируйте текст в чат Codex, открытый в checkout на Dev. Если эпизод уже известен, добавьте название базы и задания, временное окно и ожидаемый результат задания.

```text
$techexpert

На Windows Dev проверяем расследование медленного фонового задания загрузки
заказов. Работай в этом чате. Определи версию комплекта и где выполняются
инструменты. Уточни только недостающие сведения о Dev-базе, задании и времени.

Открой мастер настройки источников. Помоги выбрать серверную ИБ из списка
стартера или RAS, связать нужный узел SQL Server и указать отдельные адреса
ТЖ и остальных доступных материалов. Сохрани профиль расследования.

На первом этапе разрешены чтение выбранных источников, проверка доступов
RAC и SQL и сохранение частного расследования. Используй существующие
Dev-доступы. Согласуй отдельно запуск воспроизведения, удалённый сбор
и изменения в конфигурации, logcfg.xml, СУБД или кластере.

Для прошедшего эпизода проверь доступ и покрытие журнала в нужном окне.
Попробуй связать записи с конкретным запуском задания. Обоснуй выводы
ссылками на сохранённые наблюдения. Раздели очередь, выполнение и время
операций внутри задания. Отметь факты, гипотезы и пробелы в данных.
Значение «обычно» считай оценкой пользователя, пока нет замеров.
Укажи ссылку на материал базы знаний или публичный источник, если он
влияет на вывод.

Если эпизод ещё ожидается, сохрани план наблюдения и ожидание события.
Я сообщу об эпизоде в этом же чате. Продолжи по сохранённому расследованию.
Если данных для причины недостаточно, предложи одну проверку для гипотезы.

Если мы отдельно согласуем исправление, повтори измерения при сопоставимых
условиях. Покажи отдельно изменение времени и проверку результата задачи.
```

## Что сохранить по результату

В частном отчёте запишите SHA checkout, версии 1С, RAC, SQL и агентного клиента, установленную причину или степень уверенности, ограничения доступа и охвата периода. Укажите ID расследования, ревизию профиля, ссылки на свидетельства и результаты сопоставимых замеров. Для повторяющегося эпизода проверьте, что новое сообщение продолжает то же расследование.

Тест готовности подтверждает комплект. Серверную совместимость фиксируйте по фактически выполненным проверкам на Dev. Отчёт и исходные данные хранятся в частном хранилище.
