# 1C TechExpert AI

The first implemented scenario is SC-01: an order-loading background job taking 45 minutes instead of a user-reported five. The product requires interpretation by the user's existing AI harness. Local tools compute and retain evidence; they do not impersonate an independent AI diagnosis.

Run `python -m unittest discover -s tests -v` and `python techexpert.py demo` after changes to the core. Runtime code currently uses only the Python standard library. Skills and plugin metadata must reference executable commands that actually exist.

The bundled `normalized-events-v1` fixture is synthetic. Do not advertise native TJ/JR compatibility from it. Preserve the distinction between queue, execution, observed calls and root cause. Missing evidence remains unknown; identifiers are scoped by database, node, process, lifetime epoch and run. Never infer a whole job from one CALL/SCALL.

Inputs remain at independent user-selected locations. Private snapshots and investigation state default to the user's local application-data directory, not the repository. Do not commit private logs, credentials or case state. Tests may use disposable temporary directories. Saving an environment profile does not connect to a database, start a collector or alter logcfg.xml.

The canonical technical specification remains in the user's Pages. README describes only the implemented local path and its limits. Changes in this repository do not authorize publication, production changes or a new model provider.

First-run readiness is offline and capability-specific. Maintain the UTF-8/LF release inventory with `python scripts/generate_bundle_manifest.py --write` after reviewed runtime, skill, catalogue or knowledge edits; `python scripts/generate_bundle_manifest.py` must pass before packaging. The inventory detects inconsistent content, not publisher authenticity. Harness entrypoint acknowledgement is caller-reported, never independent model attestation. Do not probe configured source paths or start demo during readiness/GET. Only an explicit demo action runs the fixed bundled synthetic SC-01; preserve profile/case context, verify its saved report and source, and never silently rerun damaged results. Missing optional server tools do not block supplied-file analysis.

TJ source-check is explicit read-only inspection, never a GUI GET/save side effect. New cases embed bounded source coverage; coverage CASE_ID derives from verified saved TJ bytes without touching original paths or rewriting the old case/assessment. Recorded time ranges, numeric window intersections, nonempty fields and declared event filters do not establish full collection, clock alignment, identity, a whole job or absence of a cause. Keep file observations separate from the independently verified marker subset. Unsupported declarations may be displayed by inspection; strict analysis still rejects unsupported/conflicting profiles. Other adapters remain outside this TJ-only suitability check.

RAC and PostgreSQL expose fixed read-only operation catalogues. OS plans default to 300 seconds / 1 second and do not start collection until an explicit collect command. Saving profiles and local GUI preflight never connects, collects, changes logcfg, enables WinRM/SSH, or grants permissions. Native JR is limited to the sequential LGF/LGP profile checked on 8.3.27.1989; journal UUID and session numbers do not prove database/run ownership. LGD, SQL Server, Testpilot, CodeMode and cross-harness evaluation must not be advertised as implemented from the presence of their guidance skills.

Knowledge cards ship offline with a versioned index, applicability, status and source URLs. Licensed ITS material may inform independently authored notes; never add original books, articles, figures, credentials or the private source corpus. A retrieved card is a candidate reference, not a diagnosis. Artifacts retain private snapshots and integrity receipts outside the repository.

Incident drafts and exports are local. Review the exact sanitized text and files with the user; automatic cleanup is not anonymity certification. Raw source bundles, private provenance and pseudonym tables are not public artifacts. Only an explicit instruction to send the specific preview to the specific repository permits the current harness GitHub connector; read the resulting Issue back before recording its receipt. No local draft command publishes or verifies a remote Issue itself.

Investigations preserve immutable revisions and pin case/artifact/comparison evidence, profile, template, instructions and harness assessment. Structure/hash validation is not causal judgment. For periodic incidents use stages in the same harness chat: prepare sources and the independent bounded collection plan, save awaiting_occurrence and finish the agent's stage, then resume after the user's/external monitor's occurrence report. Distinguish reported occurrence from linked evidence, and preparation from actual collection. A daily plan is not a running daily collector; the OS launcher still bounds each run to 30 minutes. Source preparation help is bundled for Windows/Linux and exposes actual supported input formats.

Source export planning inspects explicitly selected local files and starts no 1C process. Only the separately selected Windows/file/8.3.27.1989 main-configuration export runs; Designer must receive the private shared-read copy, never the original IB. Keep fixed argv, copy/file/space/time budgets and owned Windows job cleanup. A successful editable-main dump does not establish runtime DB or historical/extension correspondence. Native capture and raw .1CD stay private; new artifacts and run directories restrict access to owner/administrators/SYSTEM on Windows. Do not alter original permissions, global logcfg, licenses or production configuration. Completed plans are replayed as saved results; interrupted/failed operations are not silently rerun. Profile-save is configuration-only and requires the caller's expected revision; GUI writes require If-Match for the displayed profile, including a pinned case snapshot. Reject stale writes without silently adopting the latest revision or overwriting an unrelated current environment.
