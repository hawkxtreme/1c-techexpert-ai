# MCP STDIO0.15: проверяемая область

13 операций SC-01 и пять команд управления доступны через локальный stdio MCP поверх того же ядра CLI. Код runtime использует стандартную библиотеку Python. Обнаружение каталога пассивно; пользовательские источники открываются только явным инструментом. Первоначально целевые тесты отсутствующего адаптера завершились RED; дальнейшие проверки покрывают оба протокола, общий результат/ошибки, доказательства и повторное чтение, долгий сбор, отмену конкретного RPC, независимого наблюдателя с тем же ключом, EOF/закрытый вывод, ограниченные сообщения и крупную выдачу без полного decode транспортом.

Официальный Python SDK1.26.0 используется только как внешний тестовый клиент протокола2025-11-25: initialize, tools/list, реальные адаптеры и JSON Schema результатов. Современный2026-07-28 проверяется отдельным stdlib-клиентом и официальной JSON Schema; это не аттестация современным SDK или конкретной версией Codex. Основания: [MCP stdio](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/stdio), [discovery](https://modelcontextprotocol.io/specification/2026-07-28/server/discover), [tools](https://modelcontextprotocol.io/specification/2026-07-28/server/tools), [основная схема](https://github.com/modelcontextprotocol/specification/blob/main/schema/2026-07-28/schema.json), [Python SDK](https://github.com/modelcontextprotocol/python-sdk).

Полный результат инструмента формируется внутри контроллера и сохраняется с проверяемой квитанцией. Лимиты собственно данных и MCP-представления различны; дополнительный текстовый блок не урезает диагностические возможности по сравнению с CLI. Доставка использует ограниченные чанки. Недоступные модельные токены/память и общий RSS дерева Linux не заменяются оценками. Вход256KiB, глубина32, два активных контроллера и восемь ожидающих вызовов; остальные схемы и пределы возвращает tools/list. Каждый активный контроллер ограничен отдельно; это не глобальный бюджет всего harness/плана.

`python scripts/mcp_sc01_smoke.py --state-dir ABSOLUTE_PRIVATE_STATE` запускает реальный MCP-процесс, импортирует baseline/cached из поставляемых преобразованных лабораторных фрагментов, сохраняет сравнение и проверяет десять устойчивых ответов из [mcp-sc01.xml](mcp-sc01.xml). Конкретный qa.xml с IDs и квитанция сохраняются вне пакета. Вопросы независимы и допускают read-only решение по подготовленным случаям; каждая требует сопоставления нескольких ответов. Ответы не передаются модели в будущей оценке.

В одном комплектном before/after сопоставимая нагрузка и совпадающий бизнес-результат не дают пять независимых пар. Поэтому статус скорости остаётся inconclusive, всего сравнения — not_verified. Автоматические cause_state остаются insufficient_data; интерпретация текущим harness выполняется отдельно. Smoke не является новым слепым диагнозом, живым воспроизведением 1С, пользовательской приёмкой или сравнительным LLM-экспериментом. CodeMode и преимущество в токенах не заявлены; реальная установка MCP в Codex требует отдельной проверки.

Windows3.14 и Linux3.12, сохранённый реальный SC-01 и один и тот же переносимый ZIP проверяются перед фиксацией checkpoint; точные команды, SHA, результаты, ресурсы и ограничения сохраняются в частных квитанциях. Сервер1С и лицензия для этих проверок не используются. Изменения не публикуются автоматически.

Независимая проверка первого кандидата выявила два отказа сессии: 401-значный integer вызывал OverflowError при проверке числа, а escaped lone surrogate в ID приводил к закрытию вывода. Исправленная валидация отклоняет их до запуска источников; регрессии проверяют следующий ping и продолжение независимого активного сбора. Первый кандидат с замечаниями не является разрешённым выпуском.
