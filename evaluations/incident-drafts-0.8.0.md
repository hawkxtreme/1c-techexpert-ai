# Локальная подготовка предложения инцидента 0.8.0

Проверяемая область: черновик из закреплённой ревизии Investigation, очистка, полный локальный HTML-предпросмотр, неизменяемые редакции, экспорт и точный план GitHub Issue. Сеть и внешняя публикация в проверках не используются.

Независимая проверка выявила пропуск quoted JSON-секретов, исходных E-ID в публичных именах и имён из словаря ЖР. Повторная проверка выявила небезопасный возврат исходного JSON после ошибки разбора (повторные экранированные ключи или штатное усечение). Регрессии воспроизвели эти случаи. Исправленная очистка удаляет секретные JSON-поля, отказывает непригодному JSON, назначает одни публичные HMAC-ID в тексте и метаданных. Словари, части и сериализованные записи ЖР требуют отдельно подготовленного текста наблюдений; исходные значения не копируются как очищенные. Смена версии очистки требует новой подготовки старых черновиков.

`tests/test_incident_drafts.py` проверяет устойчивые псевдонимы из профиля и структурированных отчётов, удаление секретов без сохранения в таблице, разрешённые публичные ссылки, исключение частных URL, кодированных исходников и двоичных фрагментов. Проверяются порча исходного свидетельства/локального предпросмотра/квитанции, потеря соответствий, сохранение условий рекомендации, состав выбранных цитат, исключение свидетельства, изменение хэша и отказ от устаревшего экспорта. Архив имеет фиксированные даты и только показанный состав. CLI проверяется отдельными процессами.

План отправки связывает репозиторий с точными title/body. Проверка сообщённого harness read-back не принимает изменённые содержимое/адресата; повторная одинаковая квитанция идемпотентна. Локальный инструмент не вызывает GitHub API и не доказывает существование Issue. Навык требует явной просьбы отправить конкретный просмотренный результат и последующего чтения через connector.

Автоматическая очистка не доказывает анонимности, достаточности свидетельств или правильности причинного объяснения. Свободный текст, SQL и коммерческие сведения требуют человеческого просмотра. Приёмка двумя реальными пользовательскими ролями и фактическая отправка Issue остаются отдельными непроведёнными проверками. Кодированные снимки исходников не обходят очистку: для них требуется подготовить отдельный обычный текст.
