# PostgreSQL: доступ к статистике и видимость запросов

Сначала проверьте версию, роль, видимость статистики и режим транзакции: `python techexpert.py postgresql capabilities --database ИМЯ`. Доступ к серверу 1С не предоставляет доступ к СУБД.

Обычная роль может видеть часть чужого сеанса, но не текст его запроса и другие защищённые поля. NULL не означает отсутствие работы. Границы видимости описаны в [документации PostgreSQL](https://www.postgresql.org/docs/17/monitoring-stats.html). Не выдавайте неполный список за доказательство отсутствия блокировки.

Команды activity и locks получают текущий снимок. Сопоставляйте PID вместе с backend_start, базой, временем и узлом: номер процесса может использоваться снова. Для переноса к запросу 1С нужна независимая связь, а не сходство текста.

Адаптер выполняет фиксированный каталог SELECT в транзакции READ ONLY с ограничениями времени; произвольный SQL, отмена запросов и сброс статистики отсутствуют. Доступ можно подготовить отдельно с администратором; сборщик не выдаёт привилегии сам.

В лаборатории выполнены все пять операций на PostgreSQL для 1С 16.15 под отдельной ролью с pg_monitor, без superuser. Это проверка конкретного окружения. Пустой список блокировок описывает момент проверки, не прошлый инцидент.
