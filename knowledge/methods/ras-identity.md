# RAC: связывать ИБ, узлы и процессы в пределах снимка

RAC даёт административные наблюдения кластера. Укажите endpoint, версию инструмента, кластер и время получения. Файловой базе этот источник не требуется.

Продукт поддерживает только чтение: clusters, infobases, servers, processes, sessions и connections. Пример: `python techexpert.py rac clusters --endpoint server:1545`. Для операций внутри кластера нужен его UUID. Вариант --docker-container использует установленный RAC выбранного контейнера; он не создаёт сервер.

Текущий список ИБ не устанавливает адрес SQL и соответствие прошлому запуску задания. Для связи сеанса с историческим ТЖ нужны совпадающие независимые идентификаторы, узел, процесс, период жизни и окно. PID и номер сеанса без этих границ недостаточны.

На изолированном стенде 8.3.27.1989 проверены RAS, чтение кластера и списка созданных баз. Полный серверный SC-01 не выполнен из-за отсутствия действующей лицензии в этом окружении и по решению пользователя пропущен. Доступность административного списка не доказывает лицензию для запуска приложения.

[Руководство 1С](https://1c-dn.com/library/tutorials/1c_enterprise_administrator_guide_client_server_mode_8_3_27/), [SQL отдельно](postgresql-visibility.md).
