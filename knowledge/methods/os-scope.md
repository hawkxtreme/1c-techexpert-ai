# Метрики контейнера и физического компьютера имеют разную область

У одного расследования могут быть разные узлы наблюдения: Windows с файловой ИБ, Linux VM Docker, контейнер PostgreSQL и клиентский сеанс. Запишите эту схему до сопоставления графиков.

В Linux-контейнере /proc может показывать CPU, память и блочные устройства ядра хоста/VM, а сеть — текущее сетевое пространство имён. Лимит контейнера и физическая память машины не взаимозаменяемы. Для Docker Desktop дисковые устройства Linux VM нельзя автоматически объявлять физическим диском Windows. На этом ПК сборщик проверен в обоих окружениях и сохраняет различие в поле scope.

Для гипотезы о хранении сопоставьте путь ИБ/SQL-данных, том внутри контейнера, виртуальный диск Docker и соответствующий том Windows. Если связь не установлена, так и укажите. Дополнительное наблюдение Windows должно быть отдельным источником.

Низкая нагрузка контейнера сейчас не исключает перегрузку общего хранилища во время прошлого инцидента. Не объединяйте счётчики разных пространств в общий процент без модели их принадлежности. Семантика блочных счётчиков описана [ядром Linux](https://docs.kernel.org/admin-guide/iostats.html).
