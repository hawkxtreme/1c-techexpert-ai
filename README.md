# 1C TechExpert AI

Помощник расследования технических инцидентов 1С в ИИ-окружении пользователя. Агент интерпретирует проблему и доказательства; локальные инструменты проверяют данные, выполняют расчёты и сохраняют расследование. Отдельные модельный API, сервер проекта и ключ ИИ не требуются.

Текущая версия **0.8.0**. Первый проверенный сценарий — SC-01: «Фоновое задание загрузки заказов выполняется 45 минут вместо обычных пяти». Дополнительно доступны ограниченные read-only RAC/PostgreSQL, сбор метрик ОС Windows/Linux, APDEX, снимки XML/BSL из каталога и Git, последовательный ЖР 8.3.27.1989 и связанная комплектная база знаний. Сохраняются ревизии расследования, шаблон, факты, гипотезы и структурированное объяснение текущего harness. Агент объясняет причину по свидетельствам; инструменты отдельно проверяют наблюдения, скорость и бизнес-результат.

## Начать

Нужен Python 3.11 или новее. Сторонних зависимостей выполнения нет. Из корня checkout:

```powershell
python techexpert.py doctor
python techexpert.py init --open-browser
python techexpert.py profile
python techexpert.py demo
```

`doctor` показывает доступные инструменты и ограничения. `init` открывает временный локальный помощник в цветах 1С: **Базы окружения → Источники → Проверка и сохранение**. Базы добавляются вручную, из явно выбранного `.v8i` или отдельной проверкой RAS. Для каждой базы хранится режим; общие ресурсы связываются с несколькими базами. SQL и RAC недоступны для файловой ИБ. Данные остаются по своим адресам. Пресет сборщика — **300 секунд / шаг 1 секунда**, оба поля изменяются в GUI и сохраняются. Сохранение и локальная проверка готовности проверяют настройки без обращения к указанным путям и серверам; доступность устанавливает отдельный запуск адаптера. Помощник завершает работу по TTL (по умолчанию 15 минут), раньше — Ctrl+C в его процессе.

В поддерживающем проектные skills окружении точка входа находится в `.agents/skills/techexpert/SKILL.md`. Примеры обращения: `$techexpert init`, `$techexpert demo`, `$techexpert продолжи случай <case_id>`. Если клиент ещё не обнаружил skill, агент может прочитать `skills/techexpert/SKILL.md` напрямую. Манифест `.codex-plugin/plugin.json` подготовлен для упаковки; клонирование само по себе не означает установленного в клиенте плагина.

## Исходный контрольный случай

В `examples/sc01/` находятся явный паспорт и три нормализованные записи:

| Событие | Время |
| --- | --- |
| Постановка | 09:00 |
| Начало | 09:04 |
| Завершение | 09:45 |

Очередь — **4 минуты**, выполнение — **41**, всего — **45**. «Обычно пять минут» помечается как сообщение пользователя, а не измеренная норма. Эти отметки не объясняют причину замедления; агент должен сохранить это ограничение и предложить обоснованную следующую проверку.

```powershell
python techexpert.py analyze examples/sc01/case.json
python techexpert.py show <case_id>
python techexpert.py evidence <case_id> s1:2
python techexpert.py knowledge "очередь выполнение"
```

Все команды возвращают JSON для текущего агента. Этот пример использует **normalized-events-v1** — внутренний контракт контрольных свидетельств. Его отметки не извлекаются из произвольной длительности ТЖ. Состав поддерживаемых входов описан в [контракте CLI](skills/techexpert/references/local-cli.md).

Снимки исходных файлов, хэши, отчёт, версия продукта и ревизия знаний сохраняются автоматически. На Windows используется `%LOCALAPPDATA%/1c-techexpert-ai`, на Linux — `$XDG_STATE_HOME/1c-techexpert-ai` либо `~/.local/state/1c-techexpert-ai`. История сохраняется до удаления пользователем. Для изолированной проверки можно задать `--state-dir <каталог>` **перед** командой. `evidence` проверяет сохранённый снимок; изменение оригинала не подменяет прежнее доказательство.

## Прочитать предоставленный ТЖ

Скопируйте [шаблон манифеста](examples/sc01/native-case.template.json) в частный каталог вне репозитория. Это незаполненный шаблон, не демонстрационные данные. Замените все `REPLACE_WITH_...` на сведения своего эпизода и путь к стабильному снимку файла. Исходные журналы остаются в выбранных вами каталогах.

Профиль **1c-tj-text-v1** принимает текстовый UTF-8 для явно указанной платформы **8.3.27.1989**. Размещение `placement` (`folders` или `plain`) и обязательный `timestamp_format` задаются раздельно. Проверьте начало настоящих записей: для короткого времени `mm:ss.tttttt` нужен `timestamp_format: "minute"`, `rotation_hours: 1` и точный `file_hour` с часовым смещением; для полной даты — `timestamp_format: "iso"` и отдельный `utc_offset`. Это правило одинаково для обоих размещений; формат времени автоматически не угадывается. Другие версии, JSON, сжатые файлы и неизвестное время требуют другого профиля. Поля `selection` и необязательный `context` описывают заявленный контекст; они не связывают записи с запуском автоматически.

```powershell
python techexpert.py analyze "путь/к/частному/manifest.json"
python techexpert.py events CASE_ID --source s1 --event CALL --property SessionID=12 --offset 0 --limit 20
python techexpert.py evidence CASE_ID EVIDENCE_ID
```

Подставьте `CASE_ID`, источник и идентификатор свидетельства из результата; имя события и значение свойства — из исследуемых данных. `events` возвращает точную выборку из сохранённого снимка, `matched_count`, `next_offset` и до 100 записей за вызов. Это число совпадений среди прочитанных записей, а не оценка полноты журналирования. `evidence` читает целую логическую запись, включая многострочные значения; длинный текст может быть усечён с признаком `truncated`.

Нативные записи показаны отдельно в `native_observations`. Один долгий `CALL/SCALL` не устанавливает очередь, начало, завершение или причину задержки всего задания. Без независимых отметок эти интервалы остаются неизвестными. Проверяйте статусы разбора и ограничения покрытия: [границы нативного SC-01](knowledge/cases/SC01-native-tj-boundaries.md). Чтение не подключается к ИБ и не меняет `logcfg.xml`.

В первоначальной проверке парсера на локальной установке 8.3.27.1989 разобраны **1096 записей из пяти файлов**, включая 162 многострочные. Создание пустой ИБ и выгрузка её конфигурации в DESIGNER прошли успешно. Проверены короткие заголовки при часовой ротации (`folders` и `plain`) и полная дата при `plain` с ротацией по размеру. В [контрольном наборе](tests/fixtures/native-tj/passport.json) сохранены три проверенных фрагмента без частных данных. Последующая проверка самой загрузки описана ниже.

## Привязать ТЖ к запуску задания

Профиль `1c-file-job-markers-v1` принимает фактический UUID в `selection.run`, снимок повторно прочитанного объекта задания и снимки входа/выхода его обработчика. Проверяется цепочка **UUID задания → номер сеанса → SESN Start/Finish с UUID сеанса → точные SDBL-маркеры с UUID задания и nonce**. Связанные записи ограничены одним снимком ТЖ, процессом, потоком и участком между маркерами. Имя и Key задания не являются идентификатором запуска; очередь не вычисляется из времени перед `Выполнить()`.

`job_correlation.job_lifecycle` показывает начало, завершение и `completed/failed/canceled/active`. Даты платформы имеют секундную точность: разность 2 с сопровождается консервативными границами 1–3 с. `job_correlation.native_link` отдельно показывает доказанную связь и её покрытие. При ошибке без выходного маркера границы задания могут быть известны, а привязка участка ТЖ — отсутствовать. Дубли идентификаторов, несовместимые источники и пробелы разбора внутри сеанса снимают привязку.

```powershell
python techexpert.py analyze tests/fixtures/job-lifecycle/completed.json
python techexpert.py events CASE_ID --linked-run --limit 20
python techexpert.py evidence CASE_ID EVIDENCE_ID
```

Этот комплектный вход — обезличенный фрагмент настоящей лабораторной записи, с [паспортом преобразований](tests/fixtures/job-lifecycle/passport.json). `--linked-run` выбирает только доказанный участок; при отсутствии связи возвращает пустую выборку с её статусом. Без флага `events` по-прежнему показывает обычные точные совпадения. Для своих материалов подготовьте частный манифест по [контракту CLI](skills/techexpert/references/local-cli.md).

Принадлежность записи и согласованность часов проверяются отдельно. В повторном реальном прогоне ТЖ и UTC-снимок обработчика разошлись примерно на 14 мс. `native_link.clock_alignment` сохраняет `not_verified`, наблюдаемые разности и предупреждение при нарушении ожидаемого временного порядка. Это не исправление смещения часов; длительности тела, сеанса и задания остаются отдельными измерениями.

На этом ПК в изолированной файловой ИБ проверены успешное и аварийное фоновые задания с одинаковым Key и разными UUID. [Пример жизненного цикла](examples/sc01/lifecycle-probe/README.md) содержит исходники тестовой конфигурации и инструкции запуска. Для произвольных исторических журналов, серверного кластера, другой платформы или Linux этот профиль не подтверждён.

## Воспроизвести замедление и проверить исправление

В [лабораторном примере загрузки](examples/sc01/order-load-probe/README.md) фоновое задание записывает 200 настоящих документов тестовой ИБ по синтетическому CSV. Исходный обработчик последовательно запрашивает HTTP-каталог для каждой строки, хотя товаров всего 10. Исправление кэширует неизменяемые данные товара в пределах одного задания. Общая процедура записи документов остаётся той же. Тестовый каталог работает только на loopback, имеет ограничения времени и количества запросов; конфигурация предназначена для отдельной пустой ИБ.

На Windows / файловой ИБ / **8.3.27.1989** выполнены пять пар с чередованием порядка и восстановлением одного закрытого снимка ИБ перед каждым запуском. Медиана платформенного выполнения — **13 → 3 с**, запросы — **200 → 10** в каждой паре. Во всех десяти запусках контроллер повторно прочитал 200 документов; идентификаторы, SKU, количество, цена, сумма и ревизия каталога совпали с ожидаемыми. Даже с секундной точностью консервативное сокращение медианы составило **66,7%**. Медиана отдельно измеренного участка загрузки — **12 661 → 2 500 мс**. Эти интервалы не складываются с HTTP-временем.

Это реальное исполнение на лабораторных данных в масштабе секунд. Производственный эпизод 45 минут не воспроизводился. [Карточка расследования](knowledge/cases/SC01-order-load.md) объясняет механизм, доказательства и ограничения. [Паспорт](tests/fixtures/order-load/passport.json) описывает обезличивание двух комплектных записей.

```powershell
python techexpert.py analyze tests/fixtures/order-load/baseline.json
python techexpert.py analyze tests/fixtures/order-load/cached.json
python techexpert.py compare --before BEFORE_CASE_ID --after AFTER_CASE_ID
python techexpert.py comparison COMPARISON_ID
```

Подставьте полученные идентификаторы. Одна комплектная пара показывает факты и корректность данных, но даёт `performance: inconclusive`: для подтверждения ускорения нужны **пять отдельных пар**, перечисленных после `--before` и `--after` в соответствующем порядке. Повторный анализ одного запуска не заменяет повтор эксперимента. Проверяются UUID, объём и хеш CSV, каталог, исходный снимок ИБ, версия платформы, наблюдаемое имя компьютера и аттестованный хеш реализации HTTP-сервиса. Метка компьютера и хеши не удостоверяют физический узел или подлинность внешних файлов.

`order_load` разделяет проверку бизнес-результата, фактические HTTP-вызовы, условия захвата и длительности. `compare` сохраняет JSON и читаемый Markdown рядом с неизменяемыми исходными расследованиями; `comparison` проверяет их целостность при продолжении. CLI не объявляет причину автоматически. ТЖ привязан к каждому UUID задания; внутри маркеров по 1005 SDBL-записей. HTTP-свидетельства получены из обработчика и локального сервиса, а не из предположения о наличии HTTP-события в ТЖ. Очередь и синхронизация разных часов остаются неизвестными.

Маршрут навыка также прошёл [слепую проверку в Codex](evaluations/sc01-codex-skill.md): свежий агент получил исходные наблюдения, сам сформулировал причину и изменение, затем проверил пять пар через CLI. Его ответ зафиксирован до раскрытия исходника с готовым вариантом и последующих измерений. В проверке использованы уже собранные лабораторные данные. Отдельный запуск `codex exec` на этом ПК не прошёл из-за политики выполнения команд; успешный результат относится к текущему Codex harness.

## Дополнительные наблюдения

```powershell
python techexpert.py rac clusters --endpoint server:1545
python techexpert.py postgresql capabilities --database DATABASE --host SERVER --user OBSERVER
python techexpert.py os-plan --duration 300 --interval 1
python techexpert.py os-collect --duration 300 --interval 1
python techexpert.py os-import measurements.json
python techexpert.py apdex measurements.json --target 5 --operation post
python techexpert.py source-snapshot PATH --kind git --ref HEAD
python techexpert.py source-search ARTIFACT_ID QUERY
python techexpert.py source-read ARTIFACT_ID Module.bsl --start 1 --limit 50
python techexpert.py artifact ARTIFACT_ID
python techexpert.py artifact ARTIFACT_ID --source s1
```

Подставьте свои адреса и полученные идентификаторы. RAC читает clusters/infobases/servers/processes/sessions/connections; внутри кластера нужен `--cluster UUID`. PostgreSQL читает capabilities/activity/locks/database_stats/statements через установленный psql. Выполняется фиксированный каталог SELECT в транзакции READ ONLY с лимитами времени. Пароли CLI не принимает; используется существующий libpq-доступ. `pg_stat_statements` должен быть уже подготовлен; накопительные показатели не становятся историей отдельного инцидента.

OS-сборщик измеряет очередь и задержки дисков, IOPS/байты, CPU, доступную память и сеть. Укажите `--transport ssh --host user@node` либо `--transport winrm --host node`, если удалённый доступ и Python 3.10+ уже есть. Службы и права автоматически не меняются. Для SSH доступны `--identity-file` и `--known-hosts-file`; проверка ключа сервера сохраняется. Проверены локальный Windows PDH, Linux /proc и SSH до непривилегированного Linux-пользователя. WinRM-лаунчер реализован, но реальный удалённый профиль на этом ПК не подтверждён: служба остановлена и не включалась. Каждый запуск ограничен длительностью и объёмом; неизвестные счётчики не заменяются нулями. Диски Linux VM Docker не объявляются физическими дисками Windows.

APDEX принимает нормализованный массив измерений `id`, `operation`, `started_at` с часовым поясом, `duration_seconds`, `success`. Это не адаптер любой БСП-выгрузки. Снимок исходников принимает XML/BSL из каталога или существующего локального Git: до 5000 файлов / 8 МиБ, без архивов. Git фиксирует commit без clone/fetch и чтения рабочего дерева через status/diff; незакоммиченные файлы для этого пути не включаются. Для каталога снимок проверяет неизменность метаданных при чтении. Соответствие рабочей конфигурации остаётся неизвестным без независимого подтверждения.

Последовательный ЖР файловой 8.3.27.1989 читается напрямую, без XML-входа:

```powershell
python techexpert.py jr-import "D:\snapshots\1Cv8Log" --platform-version 8.3.27.1989 --utc-offset=+03:00
python techexpert.py jr-events ARTIFACT_ID --event '_$Job$_.Start'
python techexpert.py jr-record ARTIFACT_ID RECORD_ID
```

Нужны `1Cv8.lgf` и относящиеся к периоду `.lgp`: до 32 файлов / 64 МиБ, 16 МиБ на файл, 100 000 записей, 256 КиБ на запись. Хранятся точные байты и хэши, частичный хвост и неизвестные ссылки словаря показываются явно. Без известного смещения время остаётся локальным. На реальном ЖР разобрано 13 485 записей, десять временных окон сверены с независимыми данными SC-01; публичный набор содержит пять обезличенных записей. Полнота инцидента, связь с ИБ и UUID задания этим не доказываются. LGD, другие версии и чтение активно меняющегося комплекта не подтверждены.

Расследование сохраняет шаблон TPL-01–TPL-10, отдельные время и масштаб, профиль конкретной ревизии, ссылки на случаи/артефакты/сравнения, факты, пять состояний гипотез, противоречия, объяснение harness и независимые признаки проверки исправления. `investigation-create request.json`, `investigation-update ID patch.json --expected-revision N` и `investigation ID [--revision N]` сохраняют и проверяют report.json/report.md. Агент готовит JSON из диалога; пользователю не требуется редактировать его вручную. Контракт и примеры — в [описании CLI](skills/techexpert/references/local-cli.md). Проверка структуры и хэшей не доказывает правильности причинного объяснения.

`init --investigation ID` открывает тот же помощник источников с описанием из чата, выбором шаблона/времени/масштаба и привязкой профиля. У источников есть назначение, серое пояснение ожидаемого формата и примера, права и подготовка для Windows/Linux. `source-help TYPE` возвращает ту же справку без браузера.

Для редкого повторения агент сначала готовит источники и план, затем сохраняет `awaiting_occurrence` и завершает этап. Разрешённый сбор/мониторинг работает самостоятельно. После сообщения «событие случилось» пользователь возвращается в тот же чат; сохраняется отдельное сообщение об эпизоде и продолжается `analyze_episode`. Сообщение, готовность настройки, факт сбора и подтверждение эпизода данными различаются. Окно, например сутки, задаётся отдельно от короткого запуска ОС; сохранение плана не запускает долгий процесс. Сценарий возобновления проверен программно, реальное суточное наблюдение не выполнялось.

Эти результаты сохраняются как **artifact_id** с исходными байтами, параметрами, хешами и квитанцией целостности. Они независимы от **case_id** SC-01; их связывает и интерпретирует текущий агент. Большие исходники и приватные SQL-тексты не следует целиком передавать в контекст или публиковать.

В поставке есть **17 связанных карточек знаний** и **17 профильных навыков плюс входной techexpert**. Поиск `knowledge` работает без сети, показывает статус, применимость, связанные карточки и URL. Из ИТС опубликованы собственные диагностические заметки по двум прочитанным материалам; исходные статьи, книги и изображения не включены. Некоторые навыки описывают подготовку ещё не реализованного адаптера — это отмечено явно.

На этом ПК построены из официального пользовательского дистрибутива Linux 1С 8.3.27.1989 и подписанных пакетов PostgreSQL для 1С 16.15 отдельные Docker-образы. Проверены RAS, создание тестовой серверной ИБ и SQL-наблюдения под ролью без superuser. Полная загрузка конфигурации и серверный SC-01 **не подтверждены**: действующей лицензии для этой среды нет; по решению пользователя лицензионные шаги на этом ПК пропущены. Дистрибутивы, лицензии и приватные данные в пакет не входят.

## Проверка и упаковка

Для предложения инцидента в базу знаний агент готовит локальный черновик из выбранной ревизии расследования: `incident-draft INVESTIGATION_ID --summary`. Ответ содержит путь к полному HTML-предпросмотру. Названия из профиля и структурированных отчётов, адреса, идентификаторы и пути заменяются устойчивыми псевдонимами; обнаруженные секреты удаляются. Соответствия сохраняются только в частном состоянии пользователя. Это помощник очистки: свободный текст и коммерческие сведения всё равно требуют просмотра человеком.

`incident-preview DRAFT_ID` возвращает точные предназначенные для передачи файлы. Исходные журналы и снимки кода по умолчанию не включаются. Выбранные текстовые свидетельства (`--evidence E-ID`, до десяти) после очистки входят в файлы и текст Issue; закодированные снимки исходников требуют отдельно подготовленного текстового фрагмента. Изменение текста или исключение свидетельства создаёт новую ревизию и меняет хэш. `incident-export DRAFT_ID NEW.zip --expected-sha256 HASH` сохраняет только текущий просмотренный комплект. Полный [контракт черновика](skills/techexpert/references/incident-drafts.md) описывает исправление и подготовку отправки через GitHub-инструмент текущего harness. Реальная внешняя отправка на этом ПК не выполнялась.

```powershell
python -m unittest discover -s tests -v
python scripts/package_plugin.py .local/1c-techexpert-ai-0.8.0.zip
```

Сборщик включает только перечисленные публичные файлы комплекта; рабочие данные, `.git` и кэши не попадают в ZIP. Выходной файл должен быть новым. Проверка пакета распаковывает его во временный каталог и запускает тот же SC-01. CI настроен для Windows/Linux и Python 3.11/3.14; локальный результат не выдаётся за состоявшийся облачный прогон.

## Границы пилота

Работают расчёты и деградация выводов при неполных свидетельствах, изолированная история, проверяемые ссылки, GUI профиля, импорт стартера/RAS, дополнительные наблюдения и навыки агента. Проверенные профили и ограничения указаны выше; новая среда требует своей проверки.

Чтение ТЖ и ЖР ограничено описанными профилями; оно не является полной проверкой SC-01 на рабочей системе. LGD, SQL Server, полный Testpilot, изолированный CodeMode/MCP и их сравнительный эксперимент, автоматическое обновление ещё не реализованы. Для GitHub Issue реализованы локальные черновик, предпросмотр, экспорт, точный план отправки и квитанция о сообщённом harness результате; отдельного сетевого издателя нет, фактическая отправка не проверена. Комплектный сборщик ОС выполняет один ограниченный запуск до 30 минут; суточное окно в плане не запускает суточный сбор автоматически. Общий исполнитель плана, глобальный контроль расхода harness, пользовательские варианты шаблонов и автоматическое восстановление прерванной записи пока не реализованы. Наличие навыка или поля профиля не означает готового адаптера. Приёмка удобства двумя реальными пользовательскими ролями пока не выполнена. XML-выгрузка ЖР и архивы исходников не поддерживаются по согласованным требованиям. Лицензия распространения ещё не выбрана; пакет не опубликован.

Ошибки и предложения: [GitHub Issues](https://github.com/hawkxtreme/1c-techexpert-ai/issues/new/choose). Публикуйте только подготовленные обезличенные материалы после проверки. Частные журналы, секреты и сохранённые расследования в Git не добавляются.
