# 1C TechExpert AI

Помощник расследования технических инцидентов 1С в ИИ-окружении пользователя. Агент интерпретирует проблему и доказательства; локальные инструменты проверяют данные, выполняют расчёты и сохраняют расследование. Отдельные модельный API, сервер проекта и ключ ИИ не требуются.

Текущая версия **0.2.0 — локальный пилот SC-01**: «Фоновое задание загрузки заказов выполняется 45 минут вместо обычных пяти». Полный состав ТЗ реализуется поэтапно. Доступны синтетический контрольный пример и чтение текстового ТЖ по узкому профилю 8.3.27.1989. Разбор записи ТЖ ещё не подтверждает границы фонового задания или причину задержки; нативный ЖР пока не читается.

## Начать

Нужен Python 3.11 или новее. Сторонних зависимостей выполнения нет. Из корня checkout:

```powershell
python techexpert.py doctor
python techexpert.py init --open-browser
python techexpert.py profile
python techexpert.py demo
```

`doctor` показывает фактически доступные инструменты и ограничения. `init` открывает временный локальный помощник в цветах 1С: **Базы окружения → Источники → Сохранение**. Базы добавляются вручную или из явно выбранного `.v8i`. Для каждой базы хранится её режим; общие источники связываются с несколькими базами. Для файловой ИБ не требуется SQL. Данные остаются по своим адресам; сохранение профиля не подключается к источникам и не запускает сбор. Помощник завершает работу по TTL (по умолчанию 15 минут), раньше — Ctrl+C в его процессе.

В поддерживающем проектные skills окружении точка входа находится в `.agents/skills/techexpert/SKILL.md`. Примеры обращения: `$techexpert init`, `$techexpert demo`, `$techexpert продолжи случай <case_id>`. Если клиент ещё не обнаружил skill, агент может прочитать `skills/techexpert/SKILL.md` напрямую. Манифест `.codex-plugin/plugin.json` подготовлен для упаковки; клонирование само по себе не означает установленного в клиенте плагина.

## Исходный контрольный случай

В `examples/sc01/` находятся явный паспорт и три нормализованные записи:

| Событие | Время |
| --- | --- |
| Постановка | 09:00 |
| Начало | 09:04 |
| Завершение | 09:45 |

Очередь — **4 минуты**, выполнение — **41**, всего — **45**. «Обычно пять минут» помечается как сообщение пользователя, а не измеренная норма. Эти отметки не объясняют причину замедления; агент должен сохранить это ограничение и предложить обоснованную следующую проверку.

```powershell
python techexpert.py analyze examples/sc01/case.json
python techexpert.py show <case_id>
python techexpert.py evidence <case_id> s1:2
python techexpert.py knowledge "очередь выполнение"
```

Все команды возвращают JSON для текущего агента. Этот пример использует **normalized-events-v1** — внутренний контракт контрольных свидетельств. Его отметки не извлекаются из произвольной длительности ТЖ. Состав обоих поддерживаемых входов описан в [контракте CLI](skills/techexpert/references/local-cli.md).

Снимки исходных файлов, хэши, отчёт, версия продукта и ревизия знаний сохраняются автоматически. На Windows используется `%LOCALAPPDATA%/1c-techexpert-ai`, на Linux — `$XDG_STATE_HOME/1c-techexpert-ai` либо `~/.local/state/1c-techexpert-ai`. История сохраняется до удаления пользователем. Для изолированной проверки можно задать `--state-dir <каталог>` **перед** командой. `evidence` проверяет сохранённый снимок; изменение оригинала не подменяет прежнее доказательство.

## Прочитать предоставленный ТЖ

Скопируйте [шаблон манифеста](examples/sc01/native-case.template.json) в частный каталог вне репозитория. Это незаполненный шаблон, не демонстрационные данные. Замените все `REPLACE_WITH_...` на сведения своего эпизода и путь к стабильному снимку файла. Исходные журналы остаются в выбранных вами каталогах.

Профиль **1c-tj-text-v1** принимает текстовый UTF-8 для явно указанной платформы **8.3.27.1989**. Размещение `placement` (`folders` или `plain`) и обязательный `timestamp_format` задаются раздельно. Проверьте начало настоящих записей: для короткого времени `mm:ss.tttttt` нужен `timestamp_format: "minute"`, `rotation_hours: 1` и точный `file_hour` с часовым смещением; для полной даты — `timestamp_format: "iso"` и отдельный `utc_offset`. Это правило одинаково для обоих размещений; формат времени автоматически не угадывается. Другие версии, JSON, сжатые файлы и неизвестное время требуют другого профиля. Поля `selection` и необязательный `context` описывают заявленный контекст; они не связывают записи с запуском автоматически.

```powershell
python techexpert.py analyze "путь/к/частному/manifest.json"
python techexpert.py events CASE_ID --source s1 --event CALL --property SessionID=12 --offset 0 --limit 20
python techexpert.py evidence CASE_ID EVIDENCE_ID
```

Подставьте `CASE_ID`, источник и идентификатор свидетельства из результата; имя события и значение свойства — из исследуемых данных. `events` возвращает точную выборку из сохранённого снимка, `matched_count`, `next_offset` и до 100 записей за вызов. Это число совпадений среди прочитанных записей, а не оценка полноты журналирования. `evidence` читает целую логическую запись, включая многострочные значения; длинный текст может быть усечён с признаком `truncated`.

Нативные записи показаны отдельно в `native_observations`. Один долгий `CALL/SCALL` не устанавливает очередь, начало, завершение или причину задержки всего задания. Без независимых отметок эти интервалы остаются неизвестными. Проверяйте статусы разбора и ограничения покрытия: [границы нативного SC-01](knowledge/cases/SC01-native-tj-boundaries.md). Чтение не подключается к ИБ и не меняет `logcfg.xml`.

На локальной установке 8.3.27.1989 разобраны **1096 записей из пяти файлов**, включая 162 многострочные. Создание пустой ИБ и выгрузка её конфигурации в DESIGNER прошли успешно. Проверены короткие заголовки при часовой ротации (`folders` и `plain`) и полная дата при `plain` с ротацией по размеру. В [контрольном наборе](tests/fixtures/native-tj/passport.json) сохранены три проверенных фрагмента без частных данных. Это проверка чтения настоящего ТЖ; задание загрузки заказов и его замедление здесь ещё не воспроизводились.

## Проверка и упаковка

```powershell
python -m unittest discover -s tests -v
python scripts/package_plugin.py .local/1c-techexpert-ai-0.2.0.zip
```

Сборщик включает только перечисленные публичные файлы комплекта; рабочие данные, `.git` и кэши не попадают в ZIP. Выходной файл должен быть новым. Проверка пакета распаковывает его во временный каталог и запускает тот же SC-01. CI настроен для Windows/Linux и Python 3.11/3.14; локальный результат не выдаётся за состоявшийся облачный прогон.

## Границы пилота

Работают расчёты и деградация выводов при неполных свидетельствах, изолированная история, проверяемые ссылки, GUI профиля, импорт стартера и навыки агента. В комплект входят учебная карточка SC-01 и методика с явными статусами. Навыки `logcfg` и `rac` помогают подготовить дальнейшие действия.

Чтение ТЖ ограничено описанным текстовым профилем; оно не является полной проверкой SC-01 на рабочей системе. Нативный ЖР, SQL Server/PostgreSQL, WinRM/SSH-сборщик, Testpilot, автоматическое обновление и отправка GitHub Issue пока не реализованы. Наличие их полей в профиле не означает проверенного подключения. XML-выгрузка ЖР и архивы исходников не поддерживаются по согласованным требованиям. Лицензия распространения ещё не выбрана; пакет не опубликован.

Ошибки и предложения: [GitHub Issues](https://github.com/hawkxtreme/1c-techexpert-ai/issues/new/choose). Публикуйте только подготовленные обезличенные материалы после проверки. Частные журналы, секреты и сохранённые расследования в Git не добавляются.
