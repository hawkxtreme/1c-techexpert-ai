# 1C TechExpert AI

Помощник расследования технических инцидентов 1С в ИИ-окружении пользователя. Агент интерпретирует проблему и доказательства; локальные инструменты проверяют данные, выполняют расчёты и сохраняют расследование. Отдельные модельный API, сервер проекта и ключ ИИ не требуются.

Текущая версия **0.39.0**. Общий механизм связывает окружение и независимые источники, сохраняет ход расследования, факты, гипотезы и объяснение агента. Он используется для технических проблем 1С: замедлений, ошибок, зависаний, блокировок и других инцидентов. Набор полезных проверок определяется задачей, доступными данными и фактическими возможностями адаптеров.

Реализованы помощник настройки источников, ограниченные read-only RAC, PostgreSQL и SQL Server 2022, сбор метрик ОС Windows/Linux, APDEX, снимки исходников из каталога и Git, проверенные профили ТЖ и последовательного ЖР, частная выгрузка основной конфигурации и связанная комплектная база знаний. Поддержка каждого формата и окружения имеет свои границы. SC-01 — первый сквозной контрольный пример; он служит проверке механизма и не задаёт маршрут для каждой пользовательской задачи.

Обычный нативный ТЖ принимается общим манифестом schema2 без меток SC-01 или придуманного запуска задания. Агент подготавливает его из настроек источника. Записи можно искать по периоду с точными свидетельствами; время записи не устанавливает границы действия, а успешный разбор не подтверждает причину. Поддержанный временной профиль и версия остаются обязательными.

## Начать

Нужен Python 3.11 или новее. Сторонних зависимостей выполнения нет. Из корня checkout:

```powershell
python techexpert.py readiness
python techexpert.py doctor
python techexpert.py init --open-browser
python techexpert.py profile
```

`readiness` проверяет версию и целостность инструкций, навыков, шаблонов, безопасного примера и готовой базы знаний; локальный поиск проверяется без сети. Init возвращает этот же результат и показывает его в GUI. Подтверждение прочитанной точки входа передаёт текущий агент; наличие файла само по себе не доказывает его загрузки моделью. Отсутствие SQL/RAC не блокирует анализ готовых файлов, для файловой базы они неприменимы. При повреждении комплекта предлагается восстановить полную поставку с сохранением частных расследований. Отдельная кнопка «Проверить на примере» запускает синтетический SC-01 без подключения к рабочей базе; результат сохраняется для того же агента.

`doctor` показывает доступные инструменты и ограничения. `init` открывает временный локальный помощник в цветах 1С: **Базы окружения → Источники → Проверка и сохранение**. Базы добавляются вручную, из явно выбранного `.v8i` или отдельной проверкой RAS. Для каждой базы хранится режим; общие ресурсы связываются с несколькими базами. SQL и RAC недоступны для файловой ИБ. Данные остаются по своим адресам. Пресет сборщика — **300 секунд / шаг 1 секунда**, оба поля изменяются в GUI и сохраняются. Сохранение и локальная проверка готовности проверяют настройки без обращения к указанным путям и серверам; доступность устанавливает отдельный запуск адаптера. Помощник завершает работу по TTL (по умолчанию 15 минут), раньше — Ctrl+C в его процессе.

В поддерживающем проектные skills окружении точка входа находится в `.agents/skills/techexpert/SKILL.md`. Примеры обращения: `$techexpert init`, `$techexpert demo`, `$techexpert продолжи случай <case_id>`. Если клиент ещё не обнаружил skill, агент может прочитать `skills/techexpert/SKILL.md` напрямую. Плагин поставляется с манифестом, каталогом установки и локальным MCP-сервером. Для установки используйте чистую распакованную поставку; команда `python3 --version` должна запускать Python 3. В каталоге поставки выполните:

```text
codex plugin marketplace add .
codex plugin add 1c-techexpert-ai@1c-techexpert-local
```

В клиенте выберите навык `1c-techexpert-ai:techexpert` и опишите проблему либо попросите настроить источники. Установка проверена в Codex CLI 0.164.0. В полном профиле 18 навыков и 44 инструмента. Диалог в заново открытом desktop-чате проверяется отдельно. Клонирование с проектным skill остаётся самостоятельным способом работы.

Если у вас есть локальный ZIP новой версии, попросите агента сравнить его с используемым комплектом. Он покажет версии программы и знаний, изменения и состояние сохранённых операций. После подтверждения агент готовит пакет рядом с прежней версией. Установка и возврат проверены на отдельном профиле Codex CLI 0.164.0 для Windows через постоянную локальную площадку. Для установки нужно завершить активные операции в выбранном профиле. Расследования сохраняются в своём хранилище. [Команды обновления](skills/setup-and-access/SKILL.md#локальное-обновление)

Список стартера читается только по кнопке или явной команде `python techexpert.py starter-inspect [ПУТЬ]`; без пути используется стандартное расположение текущего пользователя. Связанные списки автоматически не обходятся. Происхождение настроек и ID записи сохраняются отдельно от UUID реальной ИБ. В GUI можно исправить параметры, принять обновлённые значения из списка, сопоставить выбранные записи и оставить их раздельно либо явно объединить настройки. Название и ID стартера не доказывают идентичность баз.

После явного чтения RAS сохраняются доступные свойства выбранного кластера и общие узлы. Кнопка в параметрах ИБ читает только её свойства; известные параметры СУБД можно принять как новый источник, проверив порт и доступ из среды агента. Существующие SQL-настройки автоматически не заменяются. Текущие параметры RAS не доказывают историческую принадлежность журналов. Полный маршрут с живым лицензированным кластером требует отдельной проверки.

## Необязательный контрольный пример

Команда `python techexpert.py demo` запускает отдельную синтетическую проверку комплекта. В `examples/sc01/` находятся явный паспорт и три нормализованные записи:

| Событие | Время |
| --- | --- |
| Постановка | 09:00 |
| Начало | 09:04 |
| Завершение | 09:45 |

Очередь — **4 минуты**, выполнение — **41**, всего — **45**. «Обычно пять минут» помечается как сообщение пользователя, а не измеренная норма. Эти отметки не объясняют причину замедления; агент должен сохранить это ограничение и предложить обоснованную следующую проверку.

```powershell
python techexpert.py analyze examples/sc01/case.json
python techexpert.py show <case_id>
python techexpert.py evidence <case_id> s1:2
python techexpert.py knowledge "очередь выполнение"
```

Все команды возвращают JSON для текущего агента. Этот пример использует **normalized-events-v1** — внутренний контракт контрольных свидетельств. Его отметки не извлекаются из произвольной длительности ТЖ. Состав поддерживаемых входов описан в [контракте CLI](skills/techexpert/references/local-cli.md).

Снимки исходных файлов, хэши, отчёт, версия продукта и ревизия знаний сохраняются автоматически. На Windows используется `%LOCALAPPDATA%/1c-techexpert-ai`, на Linux — `$XDG_STATE_HOME/1c-techexpert-ai` либо `~/.local/state/1c-techexpert-ai`. История сохраняется до удаления пользователем. Для изолированной проверки можно задать `--state-dir <каталог>` **перед** командой. `evidence` проверяет сохранённый снимок; изменение оригинала не подменяет прежнее доказательство.

## Сохранённые операции

Профиль окружения 2 хранит общие узлы, кластеры, экземпляры СУБД и подключения отдельно от ИБ и источников. GUI редактирует общее подключение один раз, показывает затронутые базы и источники перед сохранением и оставляет SQL-имена раздельными. Прежние расследования сохраняют свою ревизию профиля. `profile --resolved` даёт агенту временное представление настроек для адаптеров; сам граф возвращает `profile`. Настройки, псевдонимы и сообщённые идентификаторы не доказывают принадлежность записей. Смена подключения сбрасывает устаревшие заявления о соответствии экземпляра и правах; сохранение не устанавливает соединение.

`capabilities` описывает 37 диагностических операций и два инструмента программной обработки: схемы, источники, права и пределы. Общий каталог включает ТЖ, ЖР, исходники, APDEX, ОС, RAC, PostgreSQL, SQL Server, клиентские измерения и контекст принадлежности источников в пределах проверенных профилей. Агент подготавливает частный запрос и сохраняет ключ шага перед `operation-run REQUEST.json`. Повтор ключа проверяет прежний результат и снимки, сохраняя один импорт/сбор. `operation-status`, `operation-result`, `operation-cancel` и `operation-reconcile` позволяют продолжить после перерыва; запрос отмены отделён от подтверждения остановки. Старые расследования и профиль не переписываются.

При межисточниковом выводе агент сохраняет паспорта использованных материалов: что указано пользователем, что прочитано из проверенного снимка и что неизвестно. `investigation.sources` читает этот контекст для конкретной ревизии; короткий вариант — `source-context INVESTIGATION_ID --revision N`. Совпадение имени базы, UUID журнала или номера сеанса не подтверждает принадлежность. Непроверенная связь отмечается у зависящих от неё выводов; независимый анализ остаётся доступен. Новые ревизии используют схему расследования 2, старые читаются без перезаписи. GUI показывает относящееся к выбранному выводу уточнение без новых обязательных полей.

Управляемые CLI-команды выполняют приём запроса, повторное чтение и финальную запись в отдельном ограниченном процессе. Возвращаемый `kernel_call_id` ведёт к квитанции `kernel-call CALL_ID`: длительности, доступные CPU/память и область измерения. Windows ограничивает Job контроллера вместе с вложенными исполнителями; Linux сохраняет предел адресного пространства каждого процесса, общий пик дерева остаётся неизвестным. Штатная отмена локального сборщика сохраняет частичные отсчёты. Доставка ответа и небольшой транспорт ограничены размером; это не контроль ресурсов harness/модели или удалённого узла. Подробности — в [контракте операций](skills/techexpert/references/operations.md) и [профиле проверок](evaluations/kernel-0.14.0.md). Другие прямые команды пока имеют прежние, более узкие гарантии.

Сохранённые источники можно сопоставить через `source.compare`: агент выбирает `before` и `after` со ссылками `kind` (`case` или `artifact`), `id` и `source_id`. Проверка читает частные снимки, показывает совпавший префикс, наблюдаемое изменение файла, подтверждённый повтор входного материала и незавершённый хвост. Она не требует серии запусков фонового задания. Для новой части ТЖ предлагается диапазон чтения с учётом старого хвоста; при изменении временного профиля требуется повторная интерпретация всех текущих байтов. Прежние события и отчёты не объединяются и не переписываются. Неизвестное происхождение остаётся неизвестным; равные байты разных файлов не доказывают дубли событий.

Для сравнения с обычным выполнением агент может вызвать `sample.describe` по выбранным сохранённым случаям и артефактам нормализованных измерений APDEX. Результат содержит период начала операций, размер выборки, медиану, диапазон, MAD, межквартильный размах и процентили с методом расчёта. Неудачные, неизвестные и исключённые наблюдения учитываются явно; медленные значения сохраняются. Заявленные версия, объём, условия и «обычно пять минут» отделены от измеренных длительностей. Описание выборки не подтверждает, что она нормальная, независимая или сопоставимая с инцидентом. Команды и JSON подготавливает агент, GUI остаётся настройкой источников.

Подготовка ТЖ доступна через `logcfg.prepare`: агент получает отдельные `logcfg.xml`, `change.diff`, исходную копию и план проверки/остановки. `logcfg.rollback_plan` готовит возврат по свежей копии, сохраняя посторонние правки и обнаруживая конфликт собственного блока. Профиль ограничен 8.3.27.1989 и явно выбранными событиями; рабочий файл не меняется, реальное применение и поступление событий остаются отдельной проверкой. Длительность и предел объёма в плане не являются автоматической остановкой XML.

Удалённые журналы доступны через `remote.plan`, `remote.profile_plan`, `remote.inspect`, `remote.capture`, `remote.parse`: офлайн-план, ограниченный SFTP-каталог, получение выбранных стабильных файлов и разбор частного сохранённого снимка. На удалённом Linux нужен существующий SFTPv3; локальный клиент использует OpenSSH. Сохраняются исходный узел/путь, время и целостность. Бюджет фиксируется на расследование и каждый объявленный источник; неопределённый исход не разрешает новый автоматический запуск. Протокольный лимит не измеряет весь шифрованный сетевой трафик, а SFTPv3-проверки не являются атомарным снимком или удостоверением серверной изоляции.

В мастере у ТЖ/ЖР можно выбрать локальный каталог или Linux по SSH/SFTP. SSH-адрес и доступ задаются один раз для нескольких журналов и метрик ОС; каждый журнал сохраняет собственный путь. `remote.profile_plan` готовит офлайн-план по выбранным source IDs из сохранённого профиля конкретной ревизии расследования.

## Использованные знания

Поиск знаний теперь показывает отзыв оснований, явные зависимости, конфликты и отдельные проблемы ссылок. `knowledge-use CARD_ID` сохраняет частный снимок использованных авторских карточек; `knowledge-review INVESTIGATION_ID` отмечает затронутые рекомендации. Старые отчёты и выводы остаются неизменными. Отозванные карточки не предлагаются как обычные рекомендации и не входят телом в новую поставку. Техническую применимость оценивает агент; доступность URL не доказывает истинность. [Контракт знаний](skills/techexpert/references/knowledge-lifecycle.md).

## Прочитать предоставленный ТЖ

Перед причинным объяснением агент читает `source_coverage` нового случая либо вызывает `coverage CASE_ID` для сохранённого. Проверка отличает недоступный/неподдержанный вход, пустой или повреждённый ТЖ, отсутствие записанных времён внутри окна и недостаточные поля. Первая/последняя запись, пересечение диапазонов и заявленные фильтры не подтверждают полноту или отсутствие причины. `source-check MANIFEST` позволяет отдельно проверить явно выбранные файлы перед импортом без сохранения состояния. Эта проверка относится только к поддержанному ТЖ; другие форматы не получают от неё готовности.

```powershell
python techexpert.py source-check MANIFEST --start 2026-11-16T10:00:00+03:00 --end 2026-11-16T10:05:00+03:00
python techexpert.py coverage CASE_ID --require-event SDBL --require-field Sdbl
```

`coverage` читает проверенные частные снимки и не обращается к исходным путям, не меняет старый отчёт или вывод агента. Числа относятся к файлу и заданному окну; принадлежность конкретному заданию проверяется отдельно. [Контракт покрытия](skills/techexpert/references/source-coverage.md) описывает границы времени, поля и ограничения.

Скопируйте [шаблон манифеста](examples/sc01/native-case.template.json) в частный каталог вне репозитория. Это незаполненный шаблон, не демонстрационные данные. Замените все `REPLACE_WITH_...` на сведения своего эпизода и путь к стабильному снимку файла. Исходные журналы остаются в выбранных вами каталогах.

Профиль **1c-tj-text-v1** принимает текстовый UTF-8 для явно указанной платформы **8.3.27.1989**. Размещение `placement` (`folders` или `plain`) и обязательный `timestamp_format` задаются раздельно. Проверьте начало настоящих записей: для короткого времени `mm:ss.tttttt` нужен `timestamp_format: "minute"`, `rotation_hours: 1` и точный `file_hour` с часовым смещением; для полной даты — `timestamp_format: "iso"` и отдельный `utc_offset`. Это правило одинаково для обоих размещений; формат времени автоматически не угадывается. Другие версии, JSON, сжатые файлы и неизвестное время требуют другого профиля. Поля `selection` и необязательный `context` описывают заявленный контекст; они не связывают записи с запуском автоматически.

Для дописываемого локального файла агент может явно выбрать `read_mode: "tj-prefix-v1"` у источника этого профиля. Чтение фиксирует размер, дважды проверяет те же байты и сохраняет префикс вместе с незавершённым хвостом. Новые данные остаются следующему снимку; обнаруженные обрезка, замена или изменение префикса дают ошибку источника без автоматического повтора. В `acquisition` видны границы, хэш, наблюдённый рост и ограничения. Это проверка повторяемости прочитанных байтов, без гарантии атомарного снимка, полноты сбора или согласованности нескольких файлов. Совместимость с активным писателем самой платформы отдельно не подтверждена. По умолчанию остаётся стабильный вход; выбранные файлы каталога/ZIP используют его.

```powershell
python techexpert.py analyze "путь/к/частному/manifest.json"
python techexpert.py events CASE_ID --source s1 --event CALL --property SessionID=12 --offset 0 --limit 20
python techexpert.py evidence CASE_ID EVIDENCE_ID
```

Подставьте `CASE_ID`, источник и идентификатор свидетельства из результата; имя события и значение свойства — из исследуемых данных. `events` возвращает точную выборку из сохранённого снимка, `matched_count`, `next_offset` и до 100 записей за вызов. Это число совпадений среди прочитанных записей, а не оценка полноты журналирования. `evidence` читает целую логическую запись, включая многострочные значения; длинный текст может быть усечён с признаком `truncated`.

Для набора файлов, каталога или ZIP агент вызывает `input.inspect` через управляемый CLI/MCP и показывает состав, размеры и ограничения. Просмотр сохраняет только частный каталог метаданных. После выбора файлов `case.analyze` с `input_plan` принимает в манифесте ID записей каталога, повторно проверяет исходные байты и сохраняет обычный случай со свидетельствами. Поддержаны текущие форматы case-анализатора. Для комплекта нативного ЖР и JSON метрик ОС/APDEX выбранные записи того же плана принимают `jr.import`, `os.import` и `apdex.import`: добавляются парные `input_plan` и `members`, а `path`/`measurements` указывает исходный выбранный корень. ЖР требует словарь и части из одной группы; метрики — один выбранный файл. Форматы и их ограничения остаются у прежних парсеров. Исходники подключаются каталогом/Git, без архивов. Пределы: 16 корней, 128 файлов в просмотре, 32 выбранных источника, 8 уровней, 16 МиБ на файл и 64 МиБ распакованных данных. ZIP — stored/deflate, контейнер до 65 МиБ и центральный каталог до 256 КиБ, без вложенных архивов. Сжатый поток проверяется до фактического конца; имена ZIP не задают пути записи.

При запросе сохранённых событий и фрагментов ТЖ читается блоками до 64 КиБ, без списка всех событий в памяти. Контрольная сумма всего снимка проверяется перед выдачей результата, в том числе при ограничении числа записей. Импорт сохраняет прежние пределы: 16 МиБ на файл, 64 МиБ на комплект, 100 000 попыток разбора, 256 КиБ на запись. Это не поддержка произвольного большого файла, ZIP или чтения активно меняющегося оригинала.

Нативные записи показаны отдельно в `native_observations`. Один долгий `CALL/SCALL` не устанавливает очередь, начало, завершение или причину задержки всего задания. Без независимых отметок эти интервалы остаются неизвестными. Проверяйте статусы разбора и ограничения покрытия: [границы нативного SC-01](knowledge/cases/SC01-native-tj-boundaries.md). Чтение не подключается к ИБ и не меняет `logcfg.xml`.

В первоначальной проверке парсера на локальной установке 8.3.27.1989 разобраны **1096 записей из пяти файлов**, включая 162 многострочные. Создание пустой ИБ и выгрузка её конфигурации в DESIGNER прошли успешно. Проверены короткие заголовки при часовой ротации (`folders` и `plain`) и полная дата при `plain` с ротацией по размеру. В [контрольном наборе](tests/fixtures/native-tj/passport.json) сохранены три проверенных фрагмента без частных данных. Последующая проверка самой загрузки описана ниже.

## Привязать ТЖ к запуску задания

Профиль `1c-file-job-markers-v1` принимает фактический UUID в `selection.run`, снимок повторно прочитанного объекта задания и снимки входа/выхода его обработчика. Проверяется цепочка **UUID задания → номер сеанса → SESN Start/Finish с UUID сеанса → точные SDBL-маркеры с UUID задания и nonce**. Связанные записи ограничены одним снимком ТЖ, процессом, потоком и участком между маркерами. Имя и Key задания не являются идентификатором запуска; очередь не вычисляется из времени перед `Выполнить()`.

`job_correlation.job_lifecycle` показывает начало, завершение и `completed/failed/canceled/active`. Даты платформы имеют секундную точность: разность 2 с сопровождается консервативными границами 1–3 с. `job_correlation.native_link` отдельно показывает доказанную связь и её покрытие. При ошибке без выходного маркера границы задания могут быть известны, а привязка участка ТЖ — отсутствовать. Дубли идентификаторов, несовместимые источники и пробелы разбора внутри сеанса снимают привязку.

```powershell
python techexpert.py analyze tests/fixtures/job-lifecycle/completed.json
python techexpert.py events CASE_ID --linked-run --limit 20
python techexpert.py evidence CASE_ID EVIDENCE_ID
```

Этот комплектный вход — обезличенный фрагмент настоящей лабораторной записи, с [паспортом преобразований](tests/fixtures/job-lifecycle/passport.json). `--linked-run` выбирает только доказанный участок; при отсутствии связи возвращает пустую выборку с её статусом. Без флага `events` по-прежнему показывает обычные точные совпадения. Для своих материалов подготовьте частный манифест по [контракту CLI](skills/techexpert/references/local-cli.md).

Принадлежность записи и согласованность часов проверяются отдельно. В повторном реальном прогоне ТЖ и UTC-снимок обработчика разошлись примерно на 14 мс. `native_link.clock_alignment` сохраняет `not_verified`, наблюдаемые разности и предупреждение при нарушении ожидаемого временного порядка. Это не исправление смещения часов; длительности тела, сеанса и задания остаются отдельными измерениями.

На этом ПК в изолированной файловой ИБ проверены успешное и аварийное фоновые задания с одинаковым Key и разными UUID. [Пример жизненного цикла](examples/sc01/lifecycle-probe/README.md) содержит исходники тестовой конфигурации и инструкции запуска. Для произвольных исторических журналов, серверного кластера, другой платформы или Linux этот профиль не подтверждён.

## Воспроизвести замедление и проверить исправление

В [лабораторном примере загрузки](examples/sc01/order-load-probe/README.md) фоновое задание записывает 200 настоящих документов тестовой ИБ по синтетическому CSV. Исходный обработчик последовательно запрашивает HTTP-каталог для каждой строки, хотя товаров всего 10. Исправление кэширует неизменяемые данные товара в пределах одного задания. Общая процедура записи документов остаётся той же. Тестовый каталог работает только на loopback, имеет ограничения времени и количества запросов; конфигурация предназначена для отдельной пустой ИБ.

На Windows / файловой ИБ / **8.3.27.1989** выполнены пять пар с чередованием порядка и восстановлением одного закрытого снимка ИБ перед каждым запуском. Медиана платформенного выполнения — **13 → 3 с**, запросы — **200 → 10** в каждой паре. Во всех десяти запусках контроллер повторно прочитал 200 документов; идентификаторы, SKU, количество, цена, сумма и ревизия каталога совпали с ожидаемыми. Даже с секундной точностью консервативное сокращение медианы составило **66,7%**. Медиана отдельно измеренного участка загрузки — **12 661 → 2 500 мс**. Эти интервалы не складываются с HTTP-временем.

Это реальное исполнение на лабораторных данных в масштабе секунд. Производственный эпизод 45 минут не воспроизводился. [Карточка расследования](knowledge/cases/SC01-order-load.md) объясняет механизм, доказательства и ограничения. [Паспорт](tests/fixtures/order-load/passport.json) описывает обезличивание двух комплектных записей.

```powershell
python techexpert.py analyze tests/fixtures/order-load/baseline.json
python techexpert.py analyze tests/fixtures/order-load/cached.json
python techexpert.py compare --before BEFORE_CASE_ID --after AFTER_CASE_ID
python techexpert.py comparison COMPARISON_ID
```

Подставьте полученные идентификаторы. Одна комплектная пара показывает факты и корректность данных, но даёт `performance: inconclusive`: для подтверждения ускорения нужны **пять отдельных пар**, перечисленных после `--before` и `--after` в соответствующем порядке. Повторный анализ одного запуска не заменяет повтор эксперимента. Проверяются UUID, объём и хеш CSV, каталог, исходный снимок ИБ, версия платформы, наблюдаемое имя компьютера и аттестованный хеш реализации HTTP-сервиса. Метка компьютера и хеши не удостоверяют физический узел или подлинность внешних файлов.

`order_load` разделяет проверку бизнес-результата, фактические HTTP-вызовы, условия захвата и длительности. `compare` сохраняет JSON и читаемый Markdown рядом с неизменяемыми исходными расследованиями; `comparison` проверяет их целостность при продолжении. CLI не объявляет причину автоматически. ТЖ привязан к каждому UUID задания; внутри маркеров по 1005 SDBL-записей. HTTP-свидетельства получены из обработчика и локального сервиса, а не из предположения о наличии HTTP-события в ТЖ. Очередь и синхронизация разных часов остаются неизвестными.

Для комплекта 0.4.0 сохранена [историческая слепая проверка в Codex](evaluations/sc01-codex-skill.md): свежий агент получил исходные наблюдения, сам сформулировал причину и изменение, затем проверил пять пар через CLI. Его ответ зафиксирован до раскрытия исходника и последующих измерений. Отдельный `codex exec` тогда не прошёл из-за политики запуска команд. Текущий `scripts/sc01_blind.py` готовит исполняемый частный набор с явно отобранными знаниями, сохраняет входные снимки и добавляет вторую стадию в ту же папку/state. Подготовка и техническая проверка набора не являются новым модельным прогоном.

Пароли CLI не принимает; используется существующий libpq-доступ. `pg_stat_statements` должен быть уже подготовлен; накопительные показатели не становятся историей отдельного инцидента.

Адаптер SQL Server 2022 читает текущие запросы, ожидания и блокировки через sqlcmd. Query Store возвращает агрегаты существующей истории за интервалы, пересекающие заданное окно. Доступ проверяется отдельно. [Настройка и команды](skills/sql-server/SKILL.md)

Для задержек клиентского интерфейса агент может принять файл с отметками оператора или прочитать окно и счётчики подготовленного Windows TestClient. Отдельно согласованное открытие списка сохраняет время ответа инструмента и время до наблюдения точной формы. Проверено на тонком клиенте 8.3.27.1989 с отдельно установленным Testpilot 1.9.2 на копии файловой базы. Полное проведение документа и обновление открытых форм требуют отдельного измерения. [Навык клиентской диагностики](skills/client-ui-performance/SKILL.md)

OS-сборщик измеряет очередь и задержки дисков, IOPS/байты, CPU, доступную память и сеть. Укажите `--transport ssh --host user@node` либо `--transport winrm --host node`, если удалённый доступ и Python 3.10+ уже есть. Службы и права автоматически не меняются. Для SSH доступны `--identity-file` и `--known-hosts-file`; проверка ключа сервера сохраняется. Проверены локальный Windows PDH, Linux /proc и SSH до непривилегированного Linux-пользователя. WinRM-лаунчер реализован, но реальный удалённый профиль на этом ПК не подтверждён: служба остановлена и не включалась. Каждый запуск ограничен длительностью и объёмом; неизвестные счётчики не заменяются нулями. Диски Linux VM Docker не объявляются физическими дисками Windows.

APDEX принимает нормализованный массив измерений `id`, `operation`, `started_at` с часовым поясом, `duration_seconds`, `success`. Это не адаптер любой БСП-выгрузки. Снимок исходников принимает XML/BSL из каталога или существующего локального Git: до 5000 файлов / 8 МиБ, без архивов. Git фиксирует commit без clone/fetch и чтения рабочего дерева через status/diff; незакоммиченные файлы для этого пути не включаются. Для каталога снимок проверяет неизменность метаданных при чтении. Соответствие рабочей конфигурации остаётся неизвестным без независимого подтверждения.

Последовательный ЖР файловой 8.3.27.1989 читается напрямую, без XML-входа:

```powershell
python techexpert.py jr-import "D:\snapshots\1Cv8Log" --platform-version 8.3.27.1989 --utc-offset=+03:00
python techexpert.py jr-events ARTIFACT_ID --event '_$Job$_.Start'
python techexpert.py jr-record ARTIFACT_ID RECORD_ID
```

Нужны `1Cv8.lgf` и относящиеся к периоду `.lgp`: до 32 файлов / 64 МиБ, 16 МиБ на файл, 100 000 записей, 256 КиБ на запись. Хранятся точные байты и хэши, частичный хвост и неизвестные ссылки словаря показываются явно. Без известного смещения время остаётся локальным. На реальном ЖР разобрано 13 485 записей, десять временных окон сверены с независимыми данными SC-01; публичный набор содержит пять обезличенных записей. Полнота инцидента, связь с ИБ и UUID задания этим не доказываются. LGD, другие версии и чтение активно меняющегося комплекта не подтверждены.

Расследование можно начать только с описания проблемы: шаблон TPL-00 и неизвестные время/масштаб не навязывают проверок. При необходимости выбираются TPL-01–TPL-10. Расследование сохраняет время и масштаб, профиль конкретной ревизии, ссылки на случаи/артефакты/сравнения, факты, пять состояний гипотез, противоречия, объяснение harness и независимые признаки проверки исправления. `investigation-create request.json`, `investigation-update ID patch.json --expected-revision N` и `investigation ID [--revision N]` сохраняют и проверяют report.json/report.md. Агент готовит JSON из диалога; пользователю не требуется редактировать его вручную. Контракт и примеры — в [описании CLI](skills/techexpert/references/local-cli.md). Проверка структуры и хэшей не доказывает правильности причинного объяснения.

Пользователь может попросить агента сохранить свой вариант вопросов и параметров через `template-save`. Он хранится частно, а расследование закрепляет точную ревизию; явные ответы пользователя имеют приоритет над defaults. Агент уточняет шаблон, время и охват в чате. Помощник показывает задачу и связывает сохранённый профиль источников с расследованием.

`investigation-materials ID` показывает файлы сохранённых ревизий, подключённые копии и связи с выводами. Размеры относятся к перечисленным файлам. Записи об отсутствующих копиях сохраняются в выдаче вместе с затронутыми свидетельствами.

Рабочую ИБ завершённой выгрузки на Windows можно убрать после [предпросмотра](skills/techexpert/references/source-export.md#хранение-рабочей-копии). Доступны проверка выбранного срока хранения и квитанция удаления.

Для сохранённого снимка случая команда `case-source-cleanup-plan CASE_ID SOURCE_ID` показывает размер и затронутые доказательства в сохранённых расследованиях и сравнениях. Удаление по одобренному плану доступно на Windows. Исторический отчёт показывает потерю воспроизводимости, срок хранения снимков настраивается отдельно.

`init --investigation ID` открывает тот же помощник источников с описанием из чата, выбором шаблона/времени/масштаба и привязкой профиля. У источников есть назначение, серое пояснение ожидаемого формата и примера, права и подготовка для Windows/Linux. `source-help TYPE` возвращает ту же справку без браузера.

Для редкого повторения агент сначала готовит источники и план, затем сохраняет `awaiting_occurrence` и завершает этап. Разрешённый сбор/мониторинг работает самостоятельно. После сообщения «событие случилось» пользователь возвращается в тот же чат; сохраняется отдельное сообщение об эпизоде и продолжается `analyze_episode`. Сообщение, готовность настройки, факт сбора и подтверждение эпизода данными различаются. Окно, например сутки, задаётся отдельно от короткого запуска ОС; сохранение плана не запускает долгий процесс. Сценарий возобновления проверен программно, реальное суточное наблюдение не выполнялось.

Эти результаты сохраняются как **artifact_id** с исходными байтами, параметрами, хешами и квитанцией целостности. Они независимы от **case_id** SC-01; их связывает и интерпретирует текущий агент. Большие исходники и приватные SQL-тексты не следует целиком передавать в контекст или публиковать.

В поставке есть **17 связанных карточек знаний** и **17 профильных навыков плюс входной techexpert**. Поиск `knowledge` работает без сети, показывает статус, применимость, связанные карточки и URL. Из ИТС опубликованы собственные диагностические заметки по двум прочитанным материалам; исходные статьи, книги и изображения не включены. Некоторые навыки описывают подготовку ещё не реализованного адаптера — это отмечено явно.

На этом ПК построены из официального пользовательского дистрибутива Linux 1С 8.3.27.1989 и подписанных пакетов PostgreSQL для 1С 16.15 отдельные Docker-образы. Проверены RAS, создание тестовой серверной ИБ и SQL-наблюдения под ролью без superuser. Полная загрузка конфигурации и серверный SC-01 **не подтверждены**: действующей лицензии для этой среды нет; по решению пользователя лицензионные шаги на этом ПК пропущены. Дистрибутивы, лицензии и приватные данные в пакет не входят.

## Получить исходники выбранной базы

Если готовых XML/BSL нет, в GUI есть маршрут **«Помочь получить исходники»**. Вернитесь в текущий чат: агент использует уже известные параметры, готовит план и показывает базу, объём частной копии, каталог результата и пределы. Отдельно выбранный шаг запускает Конфигуратор на частной копии `.1CD`, затем проверяет результат и подключает immutable снимок. Пользователь не составляет JSON вручную; [контракт помощника](skills/techexpert/references/source-export.md) предназначен агенту.

```powershell
python techexpert.py source-export-plan REQUEST.json
python techexpert.py source-export PLAN_ID --expected-sha256 HASH
python techexpert.py source-export-status PLAN_ID
python techexpert.py profile-save PROFILE.json --expected-revision N
```

Проверенный профиль — **Windows / файловая 8.3.27.1989 / основная редактируемая конфигурация**. На контролируемой базе SC-01 получены семь файлов, 63 743 байта; исходная `.1CD` сохранила тот же SHA-256. Проверены поиск/чтение снимка и нормализованное соответствие обоих BSL-модулей контрольному примеру. Основная конфигурация может отличаться от рабочей конфигурации БД и исторической версии; расширения не включаются, `working_version_match` остаётся `unknown`. Linux/server/другие версии пока получают инструкцию, а не автоматический запуск.

По умолчанию копия ограничена 1 ГиБ (можно выбрать до 8 ГиБ), выгрузка — 64 МиБ, время — 120 с (до 600 с); сохраняется свободный запас 10 ГиБ. Автоматический снимок кода по-прежнему ограничен 5000 файлов / 8 МиБ. Непригодный или слишком большой снимок не объявляется подключённым. Частная копия, результат и диагностика остаются до удаления пользователем либо выбранной политики хранения. Новые каталоги операции и артефакты ограничивают доступ владельцем, Administrators и SYSTEM на Windows; исходные ACL не меняются. Сохранение GUI/профиля не запускает 1С; `profile-save` отклоняет устаревшую ревизию, сохраняя другой текущий контекст.

## Проверка и упаковка

Для предложения инцидента в базу знаний агент готовит локальный черновик из выбранной ревизии расследования: `incident-draft INVESTIGATION_ID --summary`. Ответ содержит путь к полному HTML-предпросмотру. Названия из профиля и структурированных отчётов, адреса, идентификаторы и пути заменяются устойчивыми псевдонимами; обнаруженные секреты удаляются. Соответствия сохраняются только в частном состоянии пользователя. Это помощник очистки: свободный текст и коммерческие сведения всё равно требуют просмотра человеком.

`incident-preview DRAFT_ID` возвращает точные предназначенные для передачи файлы. Исходные журналы и снимки кода по умолчанию не включаются. Выбранные текстовые свидетельства (`--evidence E-ID`, до десяти) после очистки входят в файлы и текст Issue; закодированные снимки исходников требуют отдельно подготовленного текстового фрагмента. Для ЖР агент готовит описание проверенных наблюдений; сырые словари, части и сериализованные записи в черновик не переносятся. Изменение текста или исключение свидетельства создаёт новую ревизию и меняет хэш. `incident-export DRAFT_ID NEW.zip --expected-sha256 HASH` сохраняет только текущий просмотренный комплект. Полный [контракт черновика](skills/techexpert/references/incident-drafts.md) описывает исправление и подготовку отправки через GitHub-инструмент текущего harness. Реальная внешняя отправка на этом ПК не выполнялась.

```powershell
python -m unittest discover -s tests -v
python scripts/package_plugin.py .local/1c-techexpert-ai-0.32.0.zip
```

Сборщик включает только перечисленные публичные файлы комплекта; рабочие данные, `.git` и кэши не попадают в ZIP. Выходной файл должен быть новым. Проверка пакета распаковывает его во временный каталог и запускает тот же SC-01. CI настроен для Windows/Linux и Python 3.11/3.14; локальный результат не выдаётся за состоявшийся облачный прогон.

## Границы пилота

Работают расчёты и деградация выводов при неполных свидетельствах, изолированная история, проверяемые ссылки, GUI профиля, импорт стартера/RAS, дополнительные наблюдения и навыки агента. Проверенные профили и ограничения указаны выше; новая среда требует своей проверки.

Чтение ТЖ и ЖР ограничено описанными профилями; оно не является полной проверкой SC-01 на рабочей системе. Сетевой поиск новых релизов и миграция несовместимого состояния требуют отдельной реализации. LGD и сравнительный эксперимент с MCP/CLI остаются открытыми. Ограниченный CodeMode использует общий каталог из 37 диагностических операций. Запись профиля, расследования и черновика, сохранение использованных знаний и выполнение выгрузки исходников сохраняют отдельные контракты и не входят в программный API. Для GitHub Issue реализованы локальные черновик, предпросмотр, экспорт, точный план отправки и квитанция о сообщённом harness результате; отдельного сетевого издателя нет, фактическая отправка не проверена. Комплектный сборщик ОС выполняет один ограниченный запуск до 30 минут; суточное окно в плане не запускает суточный сбор автоматически. Общий исполнитель всего плана, глобальный контроль расхода harness, и автоматическое восстановление прерванной записи пока не реализованы. Профиль содержит общие узлы, кластеры, экземпляры СУБД и подключения; доступность и принадлежность данных проверяются отдельно. Наличие навыка или поля профиля не означает готового адаптера. Приёмка удобства двумя реальными пользовательскими ролями пока не выполнена. XML-выгрузка ЖР и архивы исходников не поддерживаются по согласованным требованиям. Лицензия распространения ещё не выбрана; пакет не опубликован.

Ошибки и предложения: [GitHub Issues](https://github.com/hawkxtreme/1c-techexpert-ai/issues/new/choose). Публикуйте только подготовленные обезличенные материалы после проверки. Частные журналы, секреты и сохранённые расследования в Git не добавляются.
